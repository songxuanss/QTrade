# QTrade 一期产品范围与补齐分析

## 1. 产品定位

QTrade 第一期不做“大而全的券商系统”，而是交付一条可持续扩展的专业量化工作流：

```text
统一登录 / 权限
  -> 市场与数据采集
  -> 数据质量与资产主数据
  -> 行情与组合分析
  -> 条件与风险告警
  -> 策略开发与版本管理
  -> 可信回测与实验对比
  -> 纸面交易 / 受控实盘
  -> 订单、持仓、风险、审计与复盘
```

## 2. 目标用户

| 用户 | 主要诉求 | 一期满足方式 |
| --- | --- | --- |
| 个人专业交易者 | 快速看盘、验证策略、控制实盘风险 | 专业工作台、回测、纸面交易、单账户实盘试点 |
| 量化研究员 | 可复现研究、指标、因子、实验对比 | 策略项目、数据集版本、回测报告、参数扫描 |
| 交易执行人员 | 下单、撤单、订单状态、异常处理 | 订单生命周期、持仓、手动干预、告警 |
| 风控人员 | 限制、暴露、回撤、熔断、审计 | 风险面板、预交易检查、审计日志 |
| 管理员 | 用户、数据源、密钥、系统健康 | 管理台、SSO/OIDC、运维监控 |

## 3. 一期必须包含的功能

### 3.1 身份、租户与权限

虽然登录由 `../sso` 承担，QTrade 仍必须补齐：

- OIDC Authorization Code + PKCE 登录。
- 本地会话或 BFF 会话管理、CSRF 防护、state / nonce 校验。
- 用户、组织、工作区、角色与资源级授权。
- 角色：`viewer`、`analyst`、`trader`、`risk_manager`、`admin`。
- SSO Back-channel Logout 后本地会话失效。
- 所有敏感操作审计：登录主体、IP、时间、目标对象、变更前后状态。

### 3.2 市场数据与资产主数据

一期至少包含：

- 证券 / 期货 / 加密资产等目标市场的 instrument master。
- 交易日历、交易时段、时区、精度、最小变动价位、合约乘数。
- OHLCV 历史数据与实时行情。
- 逐笔成交或 order book snapshot（视市场与数据源授权）。
- 数据源适配器、限流、重试、幂等写入、断点续采。
- 统一 symbol mapping 与数据规范化。
- 数据质量检查：缺失、重复、乱序、跳价、成交量异常、交易日历偏差。
- 数据血缘：来源、授权、采集任务、入库批次、校验结果。
- 原始数据不可变存储与可回放。

### 3.3 分析与工作台

- 自选市场列表 / Market Watch。
- K 线、成交量、常用指标、绘图、周期切换。
- 持仓、账户、盈亏、暴露、集中度、回撤视图。
- 多资产相关性、滚动波动率、收益率分布、基准对比。
- 数据源健康与采集任务状态。
- 工作区保存、布局导入导出、键盘快捷键、命令面板。

### 3.4 告警系统

一期告警不应只做价格提醒，必须覆盖四类：

1. **行情 / 策略信号**：阈值、指标、策略状态变化。
2. **风险告警**：回撤、暴露、杠杆、单日亏损、订单频率、异常成交。
3. **数据告警**：延迟、缺口、错误、供应商失败。
4. **系统告警**：服务、队列、账户连接、余额、权限、证书。

通用能力：

- 条件表达式 / 规则构建器。
- 严重级别、去重、冷却时间、静默窗口。
- 通知渠道：站内、Email、Webhook、Telegram / Slack 可选。
- 告警确认、认领、升级、关联处置记录。
- 告警历史与规则命中回放。

### 3.5 策略管理

- 策略项目与版本管理。
- Python 策略代码、配置 schema、参数版本。
- 策略模板：趋势、均值回复、动量、网格、配对等（以目标市场适配）。
- 静态检查与安全沙箱：禁止未授权网络 / 文件 / 进程访问。
- 前视偏差与未来函数扫描。
- 运行资源限制与超时。
- 策略状态机：draft -> validated -> backtested -> paper -> approved -> live -> paused -> archived。

### 3.6 回测与实验

一期回测必须可信，至少具备：

- 事件驱动回测，支持 bar / trade / order book snapshot 输入。
- 手续费、滑点、延迟、部分成交、最小下单单位、涨跌停 / 交易时段约束。
- 初始资金、保证金、仓位、现金、多空约束、汇率折算。
- 公司行为 / 合约换月（按目标市场需要）。
- 绩效指标：总收益、年化收益、波动率、Sharpe、Sortino、Calmar、最大回撤、胜率、盈亏比、换手率、暴露、基准超额。
- 交易明细、权益曲线、回撤曲线、持仓周期、逐笔归因。
- 实验对比、参数扫描、固定随机种子、依赖版本记录。
- 产物不可变：代码 commit、数据集版本、参数、引擎版本、环境、结果。
- Walk-forward / train-test split 至少支持基础版本。

### 3.7 纸面交易与受控实盘

一期建议采用两级交付：

1. **Paper Trading 必须完整**：与实盘同一策略代码和执行接口，仅替换撮合为模拟。
2. **Live Trading 小范围试点**：只接一个券商 / 交易所，默认 feature flag 关闭。

必须包含：

- Broker / Exchange Adapter 抽象。
- 订单创建、修改、撤销、成交、 rejection、超时、部分成交。
- 账户余额、持仓、订单与券商侧对账。
- dry-run 模式。
- 人工审批与二次确认。
- 一键平仓、暂停策略、全局 kill switch。
- 下单幂等键，避免网络重试导致重复下单。
- 交易时段与市场状态检查。
- 断线重连与恢复后状态同步。

### 3.8 风控

这是专业平台不可裁剪的一期能力：

- 预交易检查：价格偏离、数量、金额、重复单、频率、买卖方向、市场状态。
- 账户 / 策略 / 标的三层限额：最大持仓、名义本金、杠杆、单日亏损、总回撤、集中度。
- 自动熔断：触发阈值后拒绝新订单、撤销未成交订单、暂停策略。
- 只读 API key 与交易 API key 权限分离。
- API key 加密存储、审计、轮换、测试网验证。
- 风险事件与处置流程。

### 3.9 管理与运维

- 数据源管理、任务重跑、数据补采。
- 用户与工作区管理；身份仍来自 SSO。
- 系统健康、队列长度、任务耗时、错误率、数据延迟。
- 结构化日志、metrics、tracing。
- 配置分环境：local / dev / staging / production。
- 备份、恢复演练、发布回滚。
- CI/CD、自动化测试、数据与引擎回归测试。

## 4. 一期明确不做

为避免范围失控，以下放到后续阶段：

- 多券商、多市场全量接入。
- 高频交易 / 低延迟机房托管。
- 复杂期权定价与波动率曲面。
- 完整做市商策略库。
- 无代码拖拽策略生成器。
- 大规模另类数据市场。
- 原生移动 App。
- 多租户 SaaS 计费与 marketplace。
- 自动 AI 炒股与无人监督自主交易。

## 5. 一期非功能验收

| 类别 | 基线要求 |
| --- | --- |
| 可用性 | 核心分析页面可用；实盘功能可独立降级 |
| 数据正确性 | 关键行情数据可追溯到来源与批次；缺失与异常有报告 |
| 复现性 | 同一代码、数据、参数、引擎版本重复回测结果一致 |
| 权限 | 未授权用户不能查看工作区、策略、密钥、订单 |
| 实盘安全 | 风控拒绝路径、kill switch、幂等下单、对账有测试覆盖 |
| 性能 | 一期目标：常用 1m K 线查询 p95 < 500ms；页面实时更新 < 1s |
| 可观测性 | 每个采集、回测、订单链路有 trace ID |
| 审计 | 登录、策略发布、实盘下单、密钥变更不可抵赖地记录 |
