# Goal：专业、可靠、用户友好的数据采集工作台

将 QTrade 数据采集升级为专业、可靠、用户友好的工作台，覆盖行情与因子，并先探查财务 PIT、历史成分、退市证券、公司行为和复权数据的实际能力，再落实已验证范围的接入及未确认能力的扩展接口。用户能够快速取得所需数据，理解覆盖、质量和新鲜度，处理失败，并将已发布数据用于分析。持续推进到本目标范围内的验收全部有可复核证据通过。

本文件是待启用的 Goal 内容；保存文档不代表 Goal 已启动，也不代表任何能力已经交付。

## 1. 核验现状、确定范围与来源能力

- 核验代码、OpenSpec、部署、来源授权和已有验收记录，整理实际能力、缺口及文档冲突。任务勾选不能代替执行证据。
- 优先复现并修复用户报告的“当前版本无法访问数据采集模块”问题，记录实际访问地址、部署版本、入口、角色、复现步骤和根因。检查导航、前端路由、登录会话、权限、API 地址、代理和部署配置，按证据修复；模块恢复访问属于本次必交付，先恢复基本可用性再推进新增能力。
- 服务量化研究员及专业交易者，优先完成现有 A 股历史行情、股票池、采集工作台和市场消费主流程。
- 本次必交付包括因子目录与历史因子采集、日频自动增量、数据新鲜度、发布质量门禁、用量控制，以及下述研究数据探查和扩展契约。分钟、逐笔按当前实际授权及明确选定范围分别验收，不要求接入所有供应商和类别。
- 先做数据探查再固定接入范围：优先核验现有 MaiRui Quant Pro 及基础套餐的实际权益，分别检查官方文档、账户权限、样本响应、历史可用范围、分页上限和更新时间。不将“项目尚未接入”写成“供应商不提供”，也不将“文档列出接口”写成“本账户已验证可用”。不重复购买 Pro 已包含的因子权益。
- 探查覆盖：因子元数据/最新值/历史值；财务报表及公告、修订、历史可知时间；股票池或指数历史有效成员；退市证券及代码变更；现金分红、送转、拆并股、配股等事件及关键日期；原始价格、前后复权价格、复权因子及基准。记录逐项证据与语义，最新快照、累计分红、披露日期或复权价格不能代替完整历史、事件账本、PIT 或复权体系。
- 输出可复核的数据能力矩阵及接入决策：本次必接入的行情/因子范围、其他已验证且决定接入的数据、仅能提供部分语义的数据、待确认或无权限的数据。先完成有界样本探查；缺少资料或授权时记录最小解阻条件，继续完成扩展接口，不无限等待或编造支持状态。已固定必接入项的外部失败仍按阻塞处理。
- 实施前固定验收清单、来源、数据类别、代表性规模和部署环境；确定范围后不得为完成目标而删减验收。未确定的市场或数据范围不能以泛化承诺代替。
- 来源目录分别记录市场、类别、周期、历史边界、字段单位、调整语义、更新频率、权限、配额、用途许可和证据等级。区分未配置、文档支持、样本验证和真实端到端验证，未接通入口明确禁用。
- 协调现有采集、股票池、多源和工作台变更，遵循 OpenSpec，保持规格、任务、实现和文档一致。

## 2. 易用工作台与一键处理

- 保证具有相应权限的用户能从主导航进入数据采集模块，也能直接打开模块 URL、刷新或重新登录后返回。页面和核心接口正常加载，无空白页、错误重定向、循环登录或意外 404/403/500；保留正确的权限限制，不通过绕过鉴权恢复访问。来源未配置、外部服务不可用或暂无数据时仍可打开工作台，展示具体状态及恢复操作，不能使整个模块无法访问。
- 形成“选择数据→选择范围→预览计划→执行→查看结果”的清晰流程，提供“一键补齐最近一年”和“一键重试失败部分”。
- 范围优先级：已选标的仅处理选中标的；未选标的时使用当前选中的股票池，并在提交时冻结成员快照；两者均未选时先选择范围，不创建任务，不隐式扩大到全市场。
- 日期与标的独立默认：保留用户明确设置的日期；未设置时采用最近一个自然年，以该类别最近完整且按来源更新规则应可获取的交易日或时段为结束。不得用本地最后数据日期替代结束时间而隐藏采集滞后。页面展示具体起止时间、端点语义、市场时区及默认计算依据。
- 保留已选类别、来源、周期；行情未选周期时默认日线，明确展示调整口径。默认仅补缺，完整覆盖时提示无需采集。不静默换源、换周期或截断历史范围。
- 因子可按分类搜索、查看定义并选择所需项，一键按选定标的和日期下载历史值；不隐式下载全部因子。显示每项更新频率、历史支持、覆盖和空值原因，仅支持最新值的因子不能伪装成一年历史。财务及事件数据明确日期筛选依据（报告期、可知时间或事件日期）；不支持的范围拒绝并解释。
- 清楚显示标的数、分段数、来源、覆盖、缺失、预计调用量和用量提示；预览不创建任务。明确选定范围且预检通过的常用操作可直接执行，范围扩大、来源边界不足或达到配置的确认阈值时先确认；超过硬配额不能凭确认绕过。
- 重复点击不重复创建运行。失败重试只处理失败部分，成功批次保留。取消行为明确说明对未执行、执行中及已完成工作的影响。
- 桌面、手机、键盘均可操作，表格局部滚动、页面无横向溢出。输入、任务和结果在刷新、重开后保持正确，错误给出具体原因与可执行下一步。

## 3. 可靠调度、日频增量与恢复

- 支持来源级限流、分页、退避、幂等、断点续采、分段重试及明确取消语义。冻结股票池和输入，长范围分段无意外遗漏或重叠。
- 重复提交、Worker 重启、租约过期和部分失败不破坏成功产物。聚合状态反映全部子任务，区分等待、执行、部分成功、失败、取消、无观测和完成。
- 新增可配置的日频自动补缺：保存股票池、来源、周期、市场时区、运行时间、启停状态及授权上下文；遵循交易日历和来源发布时间，不把周末休市当作采集故障。
- 自动运行使用当前有效授权，凭证不进入计划或浏览器。撤权或来源授权失效阻止执行；不可用时显示原因，不无限创建重复任务。
- 调度器及 Worker 停机恢复后有界补跑应执行任务，依靠持久化运行身份去重。手工和定时任务遵守同一限流、配额和数据一致性规则。
- 允许对来源迟到或修订数据进行有界复核；发现变化生成新版本，不覆盖历史产物或冻结研究引用。记录复核范围与成本。
- 因子按各自日频、周频、季频或日内更新规则调度；财务及事件按披露与生效规则采集并复核。不把行情交易日完整性规则直接套用到稀疏财务或事件数据，重复财报修订和事件更新保持版本及幂等。

## 4. 数据可信、发布门禁与新鲜度

- 保存不可变原始批次、转换版本、标准数据、manifest、哈希和血缘。按来源、类别、身份、周期、调整语义及版本分别计算覆盖。
- 验证标的身份、单位、精度、时区、时间标签、重复、范围、缺口和异常值。未知与零分别表达，日内有观测不能代表盘中完整。
- 建立版本化发布质量规则：格式、身份、摘要、必填值及时间范围等阻断性错误不得发布；可接受警告带明确状态发布。记录规则版本、结果和原因，阻断后可修复并重新处理。
- 缺口、异常值等规则的严重级别须按数据类别明确，不能泛化为一律阻断或一律放行。无来源停牌证据时不得把缺失解释为停牌，不生成填造行情。
- 区分已采集、检查通过、检查未通过、已发布及终端可查看。空响应记录为无观测，不冒充成功；合法无观测不被误计为价格覆盖。
- 展示数据截至时间、最近采集时间、最近成功发布时间、预期更新时刻和新鲜度状态；来源滞后、本地采集滞后及发布滞后分别说明。阈值按市场日历、类别和来源设置，过期进入健康面板及项目告警链路，重复告警可去重，恢复可追溯。
- 已发布行情进入正确标的和周期的市场图表，因子展示定义、单位、空值和版本。刷新后仍可见，不能通过旧缓存或其他标的结果伪装成功。
- 因子同时保存供应商原始值和标准值，记录因子 ID、定义/计算版本、观测日期、采集时间，以及来源实际提供的报告期、更新时间和可知时间。区分供应商因子与本地计算因子，版本变化不能无记录覆盖；未开放、无权限、无历史、合法空值和异常缺失分别呈现。
- 财务 PIT 能力单独验收：区分报告期、公告时间、当时可知时间、采集时间及修订版本；支持按研究时点选择当时可知版本，并验证修订前后取值。仅有当前修订后的历史报表或披露日期时标为普通历史财务，可知时间未知时保持未知；不得用采集时间补造历史可知时间，历史财务因子不能因此自动标为 PIT。
- 通过公开契约消费数据，保持独立采集边界。未解决的 PIT、历史成分、退市覆盖、公司行为及复权前提明确展示，采集完成不自动标为专业研究或回测就绪。
- 为后续数据扩展提供实际可用的版本化契约和来源适配接口：能力发现、数据计划、分页/游标获取、原始归档、标准化、质量规则、发布及查询共享采集生命周期；各类别使用明确类型，不依赖任意 JSON 或行情字段硬塞。最小模型包括财务版本及可知时间证据、成员有效区间、证券身份变更、公司行为事件与关键日期、复权因子/口径/基准/版本，以及因子观测与定义版本。
- 查询契约能区分观测/报告/生效时间与研究可知时间，支持明确的版本引用；按时点查询仅在来源证据充分时启用。用一个受控适配器验证新增类别能通过上述生命周期，不要求实现通用插件平台或全部后续研究系统。未接通类别公开能力状态和限制，不提供返回虚构数据的可用入口。

## 5. 完整业务验收与回归

- 遵守 AGENTS.md，主验收链路为：部署 UI→API→真实数据库→Worker→已授权真实来源响应→非空原始归档→质量门禁→标准数据发布→图表或因子浏览→刷新核验。
- 在用户实际访问的部署环境验证访问修复：授权用户登录→主导航进入→直接 URL 访问→刷新→会话过期后重新登录并返回→查看来源、任务及已有数据→执行一次真实采集并刷新结果；覆盖桌面和手机。无权限用户按预期拒绝，来源故障与空数据有可理解状态。仅开发环境页面可打开、静态构建成功或健康检查通过不能证明用户访问已恢复；若无法取得实际环境访问条件，明确记录为未完成验收。
- 覆盖单标的、多标的、股票池、默认一年、自定义范围、长范围拆分、重复补缺、全部已有、部分失败、失败重试、取消和重启恢复。
- 覆盖定时任务创建、自动触发、停用、重启补跑、重复触发去重、交易日历、新鲜度过期与恢复，以及门禁阻断、修复后发布和配额拒绝。
- 因子真实验收覆盖目录、所选因子的历史下载、默认一年、增量、缺口、空值、版本、浏览及刷新；目录数量不能代替历史值验证。对本次接入的财务/成员/事件/复权数据，分别验证时间语义、版本及消费者查询。具备 PIT 的来源须验证历史时点及后续修订隔离；不具备的须验证限制提示和不受支持查询的拒绝。
- 扩展接口通过契约测试及受控适配器验证，包括未知可知时间、版本迁移、成员区间和事件去重等关键语义；证据明确标为 fixture，不计作供应商真实接入。探查结果与 UI 能力状态一致。
- 验证角色限制、跨作用域拒绝、授权撤销及桌面/手机操作。受控故障用例与真实来源成功用例分别记录，失败路径本身按预期拒绝或恢复才算通过。
- 维护登录/权限、策略版本、数据采集、回测/报告、告警及已连接交易控制的主业务覆盖矩阵，明确真实集成、fixture、未覆盖和阻塞。未连接功能不能声称回归通过。
- 请求接受、queued、健康检查及 fixture 通过不代替真实闭环；基于真实部署状态核验最终业务结果。验收范围内用例全部通过，且无未解决的严重缺陷，才可声明交付。

## 6. 性能、用量与运维证据

- 先记录明确环境下小/中/大代表性股票池的基线，再确定响应、吞吐、资源及恢复目标并复测；分别统计平台内部耗时和供应商等待，不以少量样本外推全市场。
- 提交前提供任务量和调用量估计；估计不确定时显示依据及区间。配置来源和作用域的并发、每日调用及单次规模限制，执行阶段再次校验，避免并发绕过。存储估算可按实测样本展示，不能伪装精确报价。
- 显示实际调用、重试、限流、队列等待和存储使用，区分确认阈值与硬配额。手工、重试和定时操作共用用量控制，等待或拒绝原因可查询，避免单个大任务长期饿死其他任务。
- 提供来源健康、任务积压、数据新鲜度和失败原因的运维视图。完成至少一次真实成功、受控故障恢复及持久化结果重验。
- 验证本次数据范围的数据库、对象归档及 manifest 备份恢复一致性；在隔离环境恢复后通过查询和 UI 核验，不操作生产数据恢复。
- 交付使用说明、配置和运维手册、测试覆盖矩阵、性能及用量报告、验收证据、已知限制和后续研究能力清单。报告与截图不包含凭证。
- 同时交付数据探查报告、来源能力矩阵、字段与时间语义字典、接入决策、扩展接口说明及新增来源/类别的示例；保存脱敏样本证据与探查日期，说明哪些结论只来自文档、哪些已实测。

## 7. 推进边界、后续范围与完成条件

- 自主推进范围内代码、测试、文档和现有开发/测试部署验证，不新增付费订阅、不购买或登录新厂商账号、不删除生产数据、不扩大到真实订单。新增来源遵循现有授权及存储、导出、研究用途许可。
- 因子采集及财务 PIT、历史有效成分/退市数据、公司行为与复权的数据探查和扩展接口属于本次必交付。探查后固定可验证的接入范围：既有授权支持且纳入范围的能力必须完成真实接入验收，不能统一推迟到后续 Goal；无法确认或取得完整语义的能力必须展示缺失、证据和研究限制，并提供经验证的扩展契约。完整跨来源 PIT 重建、历史证券数据库、事件驱动持仓现金核算和完整复权研究体系可作为后续 Goal，不以部分数据接入宣称已交付。
- 本次不要求完整 L2 或低延迟实时交易数据链路；不要求重新计算供应商所有因子，亦不承诺未经验证的历史覆盖、因子准确性或无前视偏差。
- 多源能力按范围和已授权来源验收；未配置商业来源不能作为必交付接通结果，也不能用 fixture 宣称真实源可用。范围内如有多个已验证同类来源，应抽样核对口径与差异；未经证据不自动拼接或切换。
- 遵循 OpenSpec 记录新增行为和计划，日常实现选择自主决定；涉及市场范围、付费资源或研究完整性承诺变化时提出具体决策，不暗中扩大目标。
- 为新增及修改的代码补充必要注释，方便 review 理解：说明非显而易见的设计原因、领域规则、数据与时间语义、模块边界、并发/幂等及异常恢复约束；重要公开接口提供清晰文档。注释须与实现一致，不仅复述代码，不包含凭证；交付审计检查注释是否足以让未参与开发的 reviewer 理解关键行为。
- 外部阻塞记录证据、影响范围和最小解阻条件，继续不依赖该条件的工作。无法达成范围内真实验收时保留未完成状态，不隐藏失败，不用降低标准或勾选任务结束目标。
