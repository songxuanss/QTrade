# 行情/因子版本化门禁阶段

对应 OpenSpec 4.1–4.3 的规则和执行基础；完整质量状态/API/UI、传输异常、日内缺口及重处理尚未完成，相关任务不勾选。

新增严格 `CollectionQualityResult` / `CollectionQualityIssue`，规则版本 `collection-quality.v1`。结果包含作用域/子任务、输入摘要、标准记录摘要/数量、检查时间、聚合问题和 passed / warning / blocked / no_observations。结果状态与问题级别由契约交叉验证。质量身份依据输入、规则结果生成；仅检查时间改变时不重写首个记录。

Worker 流程为来源响应留存→转换→质量判断及不可变质量文件→允许后发布。主来源响应回调确实完成才可进入发布或合法无观测；只有日历响应不够。阻断写安全 unverified 失败码，不生成 manifest、不更新发布索引、消费者不可见；原响应和质量文件保留。转换本身失败仍有前阶段响应留存，但尚无此新质量结果，不能把转换异常视为完整质量运行已实现。

| 检查 | 当前级别和边界 |
|---|---|
| 无主来源归档、非法标准模型、类型/标的/因子/周期错误、范围外、重复 | 阻断 |
| A 股价格/成交额 CNY、股票量 shares、指数价格 index_points，已声明时间标签 | 不一致阻断；此单位规则限定当前 CN 行情，其他市场需要明确扩展规则 |
| 无效来源交易日历或记录落在提供日历之外 | 阻断 |
| 缺来源交易日、没有日历证据 | 警告；不解释为停牌，不补造价格 |
| 分钟完整性、适配器已有 suspect 标记 | 警告；不把每日有观测当成全部分钟完整，也未新增对供应商标志含义的保证 |
| 因子未知定义/单位/可知证据、合法带原因 null | 警告；不标为 PIT 或因子准确性认证 |
| 有确认可知证据且时间在检查时点之后 | 阻断 |
| 实际空响应、无标准记录 | no_observations，不计价格覆盖、不发布 |

质量文件位于子任务目录 `quality-{quality_id}.json`，沿用原子不可变写及 scoped 身份检查。既有 v1 发布 schema、manifest 字节和冻结引用不修改；已发布产物的恢复路径保留兼容，不能因此说旧产物已经过新规则。当前质量文件不是公开 UI 状态接口。

受控验证：14 项新增质量测试覆盖身份/范围/重复/非法值/单位、完整日线、日历错误、缺日与日内警告、因子 null/未知语义、无观测及必要响应、Worker 阻断→原始与质量文件保留→无 manifest、重复质量判断首个时间不变，以及显式整数版本（布尔/字符串/未知/缺失拒绝）。质量报告和响应收据复用已验证的严格 DataContract 版本边界；内部构造显式提供版本。合并适配/默认/桥接测试 50 项通过，独立 PG 研究及旧行情恢复测试30项通过；Ruff/Mypy通过。阻断来源为 fixture，不能冒充真实供应商失败 UI 用例。

初版门禁 collector 镜像 `sha256:8b219eb430fe8e7fa4da683dd7535d12d72fa793f92ee6937c3861215a36317a` 的真实 13000 UI 回归 8 项（分钟384、因子5、池96）通过；一年日线运行 `75d413aa-56b9-409d-9348-7209ec842c0d` 发布242条并在农业银行图表刷新可见，默认/拒绝/桌面手机共7项通过；真实北向空历史仍 no_data/无发布并刷新通过。严格版本边界修正后镜像 `sha256:932c995105cb554391f7e33c28102583aaf0f32f52c2098d9086e9415bea2336` 已部署。

额外归档核对7子任务的质量文件：3个分钟子任务 warning（intraday_completeness_unknown / source_suspect）、1个因子 warning（定义、单位、可知时间未知）、2个年度日线 passed、1个空因子 no_observations。质量 scope/part、数量和所有已发布目标的 records_sha256 与实际 manifest 一致；原4非空发布另经公共分页/原始 Parquet/消费者校验。命令开关 `QTRADE_VERIFY_RAW_CAPTURES=true QTRADE_VERIFY_COLLECTION_QUALITY=true`，额外年度与空响应运行通过 `QTRADE_VERIFY_CAPTURE_JOB_IDS` 指定。私有脱敏报告 `independent-collector-persistence.json` 保存，无供应商响应内容或凭证输出。

最终严格版本镜像再次通过8项真实UI回归及北向空响应/刷新；7目标质量/响应收据验证通过，包含先前年度报告跨部署读取兼容。关键代码已按新增 Goal 注释要求说明检查身份与时间的分离、来源归档前提、未知因子语义和首个质量检查的不可变保留。

后续必做：持久质量索引及公开版本查询/状态 UI、原始完整传输留存、规则检查的完整时间标签/精度/调整前提和日内缺口、因子定义版本一致性、阻断修复后有界重处理与消费者隔离 UI。当前 passed 是本规则版本本次输入的结论，不等同专业量化研究或回测就绪。

## 质量查询接口实现阶段

新增 `GET /v1/jobs/{job_id}/parts/{part_id}/quality` 及业务 READ 桥接。服务先校验当前权限，再由 PostgreSQL 确认 scope/job/part 的实际链接，最后读取私有质量文件；不能拿别的子任务 ID 跨任务或跨空间读文件。读取无报告时返回空列表，不创建目录、不伪造 passed；超过当前有界历史上限明确失败，不静默截断。返回明确 quality_id/rule_version，保持原报告不变。

20 项质量/桥接测试、31 项真实隔离 PG 测试通过，新增 PG 测试验证准确链接及错误空间、任务和子任务拒绝；Ruff/Mypy通过。此查询接口尚未部署和接入 UI，不能将前面的 Worker 部署证据借用为新查询接口真实 UI 验收；OpenSpec 4.1 等仍未完成。
