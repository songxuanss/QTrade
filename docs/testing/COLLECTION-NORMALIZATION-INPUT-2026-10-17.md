# 行情与因子转换输入检查点

本轮从网络获取中抽出纯转换，并在转换前保存完整输入，是任务4.1/4.3/4.4的推进。**尚未提供行情/因子的公开离线重处理预览、持久入队和UI，不把此基础或直接调用归档发布的fixture当完整4.4交付；整体仍18/42。**

## 设计与兼容

- 新增独立可选PreparedCollectionProvider（fetch_prepared/normalize）及PreparedCollectionArchive。生产MaiRui获取与本地转换共用同一纯模块；转换不调用HTTP、因子目录、名称、日历或年度缓存。现有第三方旧fetch接口兼容，但不因此获得离线重处理声明。
- 新增v2 CollectionNormalizationInput与独立Schema，不改写v1请求、清单、原始和标准产物。检查点绑定完整原请求/分段/映射/标的/回执、稳定身份、准备时刻和SHA；同输入保留首次准备时间。
- 行情保留每次获取的完整RAW切片及原半开范围、日历和获取机制，先保存再解析标签/筛选时间；跨年响应按各自片段裁剪。转换保留旧单位、结束标签及09:30额外观测的未知语义，不借本轮认证分钟时段完整性。
- 因子保留实际定义/单位/计算版本，以及逐行原数值、文本信号或空值类型。Decimal以精确文本存储时另存源类型，不把数值形信号误当数值或给未知可知时间填准备时刻。未知日历可在公共输入契约显式表示，MaiRui转换仍要求其实际日历，不能用未知代替完整性。
- 文件位于原私有scope/part目录的normalization-inputs，原子写入/fsync、600/700权限；写入前核对同次租约的实际回执及正文SHA，失败不转换/发布。单回执元数据≤64KiB、源正文核验总计≤256MiB，单输入及一次枚举合计≤128MiB/100份；行情输入≤100000行、因子仍≤365行。读取自身输入校验身份/SHA，不创建目录；与来源回执的独立重验由下述精确证据脚本完成。准备时刻仅为本地持久化时刻。
- 非有限JSON数值显式拒绝，不能经序列化悄悄变null。已有发布没有检查点时保持缺失，未伪造旧上下文或重写旧研究引用。新增/修改代码注释解释类型编码、裁剪、身份、幂等、独立接口、未知时间及资源边界。

## 测试、发现与修复

`.venv/bin/python scripts/selftest-normalization-inputs.py`：**149项通过（109+20+20）**。每组使用独立随机临时PG库，只清理自有库；现有TestClient httpx弃用warning保留。覆盖：

- 获取→RAW→检查点→转换拒绝，完整输入/原字节保留；修复受控转换后纯转换→质量→新归档发布模型，原任务/字节不变。此修复流程不是持久重处理队列或live供应商故障。
- 精确18位小数、数值形文本信号、空值、原定义、未知单位/计算版本/可知时间；检查点经严格模型读取，篡改准备时刻/SHA、跨租约及正文损坏拒绝，读不存在输入不写文件。
- 无效时间标签在拒绝前已存，跨年过宽响应仍按自身片段裁剪；写入失败不调用转换，非有限值不变null。
- 真正未包裹的生产Adapter经过实际PG队列/Worker后，检查点纯转换与已发布RAW/标准一致；既有预算等待、重试、撤权、幂等、租约/调度回归保持。

初轮既有queue/quality夹具直接替换fetch，不能实现新prepared接口，造成测试失败。采用显式LegacyCollectionFixture保留这些测试原本的旧接口/预算/队列表面，未放宽原断言；新接口由独立未包裹Adapter的Worker测试覆盖，不在生产设置兼容绕过。

新测试还发现既有FactorPoint联合类型会把数值形文本信号先转为Decimal后拒绝；保留源文本，由value_kind决定数值意图，number继续通过原ExactDecimal格式/精度检查，signal按原词法往返。冻结v1 Schema生成对照及旧质量/发布回归通过，未重新生成原Schema文件。单独设置allow_inf_nan未约束JsonValue的非有限值，三项真实单元失败后补充显式检查，最终通过；部署内运行探针也验证该拒绝。
