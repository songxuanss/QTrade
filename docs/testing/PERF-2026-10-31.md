## 导航响应

修复前从“市场终端”点击“数据管理”：

- URL 切换约 1.4–2.0 秒
- 页面内容约 5 秒后才出现
- 没有路由级加载骨架

修复后（同一部署、真实登录）：

| 场景 | URL 切换 | 骨架可见 | 主内容可见 |
| --- | ---: | ---: | ---: |
| 进程冷启动后首次点击 | 49 ms | 96 ms | 942 ms |
| 预热后点击（3 次） | 37–64 ms | 82–96 ms | 884–1,381 ms |

结论：点击后 URL 与骨架在百毫秒内出现，主内容不再等待外部行业目录。

## 服务端请求

数据页并行读取的任务、批次、来源、采集器目录、偏好和已发布数据集等端点，实测大多为 49–233 ms。主要异常是外部行业目录：

- `data/universes/definitions` 冷缓存首次调用约 4.36 秒（MaiRui `hszg/list`）
- 同进程后续调用约 79–86 ms（15 分钟缓存）

修复前该调用阻塞整个数据页 RSC 输出，是首次访问“数秒”的主要原因。现在股票池目录放入独立 `Suspense` 边界：

- 默认“行情与因子”主内容不等待目录
- 直接打开“板块与股票池”时，页面外壳 1.54 秒可见，目录在 5.38 秒后完成
- 目录失败或变慢不再阻止其他分区

同一请求内的 `/auth/session` 校验改为请求级共享，变更操作复用会话已签发的 CSRF 令牌。预热后主内容从约 1.9 秒降到约 0.9 秒。

## 分段估算与来源切换

真实 UI 使用 3 个标的、2024-01-01 至 2024-12-31、5 分钟周期：

- 普通历史：`粗估约 159 个采集分段`，每标的约 53 段，提示“普通历史分钟接口按最多 7 天拆分”
- 点击“改用 Pro 分钟历史”后：来源切换为 `mairui.pro.bars`，`粗估约 3 个采集分段`，提示“当前来源按日历年组织分段”

即该样本分段数从 159 降到 3。用户此前遇到的 2,650 段在普通分钟策略下约等于 50 个标的一年；同类范围切到 Pro 后会按标的和日历年组织，而不是按 7 天切分。粗估只用于提交前判断规模，实际分段与覆盖仍以服务端预览为准。

桌面与 390px 手机均无页面横向溢出。
