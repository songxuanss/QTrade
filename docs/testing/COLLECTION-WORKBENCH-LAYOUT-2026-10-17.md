# 数据采集页分区布局验收

用户要求采集页不要过长，按专业工作台重新组织。本次采用七个一级分区、研究/资产/监控二级切换和有界记录区，避免把全部业务表单堆叠在一页。布局需求的完成以以下部署/实际UI证据为准，**不代表整个Goal或OpenSpec6.5的全部故障矩阵已完成**；整体仍18/42。

## 设计、范围与review

- DataWorkbench继续由服务器经现有公开接口装配内容，WorkbenchTabs仅管理显示、URL、键盘及焦点，不包含来源或下载业务逻辑。隐藏分区保留挂载，切换不重置表单；URL只放导航键，没有证书、响应或草稿参数。
- 行情/因子作为默认工作区；板块、财务/事件、自动更新、资产、监控、逐笔兼容按工作内容分开。运行用量/健康/来源不再挤占采集首屏，兼容API故障不误称独立采集整体不可用。
- 长任务、股票池目录/成员、更新计划、RAW/质量列表、新鲜度卡片及来源证据使用区域滚动；滚动区有名称及键盘焦点。保持原有分页，不截掉记录。桌面保留计划/最近任务侧栏，手机单列，分区栏局部横向滚动且自动显示当前项。
- 刷新、前进返回、直接URL及旧片段可恢复导航；空股票池搜索不误回行情区。未登录的分区URL经SSO回到该分区，只保留固定站内导航字段，不接受外部重定向目标。原下载、权限、Worker、归档、发布和消费契约不变。
- 关键注释解释面板持续挂载、URL边界、横向导航不改文档滚动位置，以及本地滚动/隐藏样式不可被全局section规则覆盖的原因。

## 实际UI及拒绝验证

`node tests/verification-workbench-layout.mjs --baseline`在改版前保留高度；最终按顺序运行`node tests/verification-workbench-layout.mjs`和`--mobile-only`：

- 真实SSO管理员桌面、采集READ手机及管理员手机全部通过。七个分区每次仅一个一级面板可见，四类资产子区可访问；切换保留手工标的输入，未声称未保存草稿刷新持久化。
- 左右/Home/End键、标签焦点、URL刷新、顶端刷新、前进返回、旧财务片段、空股票池搜索和非法分区回退通过。未登录直达monitor/sources经实际SSO返回原分区；手机当前标签边界在横向导航视口内。
- 新鲜度实际保存记录、11项来源能力和当前配额通过部署API读取；展开卡片≤620px，区域键盘滚动通过。来源/健康展开及所有分区axe0，无页面横向溢出，无浏览器脚本错误；只读财务预览按钮禁用。截图经人工复核。
- 本次没有新增权限接口；跨作用域/CSRF等沿用原验证范围，未将导航测试称为全站权限或新供应商验证。

### 发现与修复

初版分区导航通过后，展开新鲜度出现heading-order：原全页的二级标题不再可见，卡片直接从h1跳h3。为健康和来源summary补语义h2后实际复验通过。手机直接打开靠后分区时，选中标签在可视区外；加入仅横向滚动当前标签的效果并验证实际边界后通过，没有强制滚动整页。

并行实际登录暴露SSO认证结果在数据库提交前发布的竞态。隔离303发送探针及真实辅助函数回归定位后，在相邻SSO项目增加四处提交屏障（提交5d3a611），保留原身份库与其他未提交工作。四项隔离回归修复前失败、后通过，相关认证/OIDC共43项通过。仅重启原自有SSO，真实原身份两轮各四并行上下文共8次通过，深链接及原工作区保留；最终布局主轮亦通过。首次快速后测RP内容断言失败，无回调失败事件；显式等待实际页面标题并记录3.4–6.2秒内容准备后通过。详细证据见相邻SSO项目reports/REDIRECT-COMMIT-VISIBILITY-2026-10-17.md。此范围不代表所有历史登录故障、过期token或无限并发容量已验证。

分区拆分还修正Server Action返回位置：Tick拒绝返回逐笔区、成功返回任务区，重跑返回任务区、质量处置返回质量区、研究发布返回研究资产区；旧research结果URL也可恢复正确面板。8项受控行动路由单测通过，不替代live下载。本次实际UI填写起始晚于结束的Tick范围，真实BFF拒绝并在原分区显示业务提示，前后真实API任务列表一致、没有创建任务或请求供应商；管理员桌面/手机覆盖。
