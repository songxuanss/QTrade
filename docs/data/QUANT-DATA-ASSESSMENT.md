# A 股量化数据完整性与交易支撑评估

评估日期：2026-10-06；实施复核：2026-10-09。范围：A 股优先、公开免费来源优先。本文是选源与项目缺口评估，不代表新接口已经接通，也不代表购买建议或实盘就绪。厂商文档中的能力、账号实际权限、样本数据质量和项目端到端交付必须分别验收。

## 当前项目结论

当前生产组合接入 MaiRui 历史逐笔、未复权日线与历史分钟线，完成指定范围采集、原始 Parquet/摘要保存及研究数据集生成。真实浏览器、Worker、数据库与 MinIO 已验证近期逐笔，以及 2025 年日线和 5 分钟样本；质量报告对比来源日历与已观察到的日期。校验摘要证明文件未被篡改，不证明来源没有漏掉交易。

全历史证券状态、复权与公司行为、历史指数成分、财务 PIT、实时行情及真实 Broker 均尚未完成实际业务链路验收。项目已有证券、日历、数据集、风险与组合模型，不等于其真实数据已完整接入。当前实际回测组合使用 MockTradingEngine，不能以下载成功或样例回测成功宣称可进行可信历史研究或实盘交易。

## 完整性应按什么衡量

| 维度 | 必须核实的内容 | 不完整的后果 |
| --- | --- | --- |
| 历史深度 | 各股票/周期真正最早、最晚可得日期，牛熊与极端时期，上市以来覆盖 | 样本太短，结果只适用于近期市场 |
| 横截面 | 沪深京、退市与停牌股票、代码变更、历史股票池与指数成分 | 只用今天存活的股票回测，产生幸存者偏差 |
| 时间可见性 | 事件时间、公告时间、采集时间、修订版本；按当时可得资料查询 | 未来财报、更正数据或今天的成分进入过去回测 |
| 行情语义 | Bar/行情快照/成交逐笔/委托逐笔分开；时区、股/手、累计/增量量 | 重复计算成交量、误判盘口或把汇总数据当完整逐笔 |
| 连续性 | 交易日历、停牌、无成交、来源缺档、未归档分别标识 | 把缺档当休市，把不存在的成交填出来 |
| 一致性 | OHLC 合法、跨周期聚合、成交额量、复权与公司行为可对账 | 错误收益率、虚假交易机会、不可复现 |
| 更新与运行 | 数据延迟、完成时间、配额、断线恢复、版本、授权与成本 | 信号迟到或执行时使用陈旧价格 |

不能依据接口数量给出“完整度 90%”。在确定股票池、日期范围和策略粒度之后，才可计算实际覆盖率。

## 最小数据组合与优先级

| 优先级 | 数据 | 支撑的工作 |
| --- | --- | --- |
| P0 | 含退市的证券主数据、交易日历、历史 ST/停牌/涨跌停状态 | 历史股票池与真实可交易性 |
| P0 | 未复权日线、成交量额、复权因子、分红送转配股记录 | 趋势/动量、收益计算、公司行为与资产对账 |
| P0 | 历史行业、指数成分与权重、基准行情 | 横截面选股、行业中性、相对表现与风险归因 |
| P0（实盘） | 账户资金、持仓、可卖数量、委托、成交、撤单和费用回报 | 执行控制、订单恢复、实际收益与风控 |
| P1 | 历史分钟 OHLCV/成交额，以及实时盘口与行情时间戳 | 日内择时、成交成本、分钟策略与执行 |
| P1（基本面） | 财务三表、估值与股本历史；原公告和修订版本及可见时间 | 价值/质量/成长、多因子研究 |
| P2 | 公告、业绩预告、龙虎榜、资金流、融资融券、宏观与新闻 | 事件、资金和情绪策略；仅在明确策略需求时接入 |
| P2（高频必需） | 多年完整成交逐笔、委托/撤单、深度盘口、交易所序列与高精度时间戳 | 订单簿重建、订单流与队列策略 |

“可见时间”示例：6 月 30 日结束的半年报若在 8 月 20 日发布，7 月回测不能使用；后续更正版也不能覆盖当时已冻结的数据。复权后的价格可供研究，但实际成交应使用未复权价格，并正确处理公司行为。

## 数据来源比较

以下为文档能力和工程判断，不是所有账号已可调用的保证。

| 方案 | 研究覆盖与优势 | 关键限制 | 长期定位 |
| --- | --- | --- | --- |
| 当前 MaiRui 逐笔接入 | 已验证近期采集与原始数据落地 | 此接口从 2026-08-13 归档；仅所选股票/时段，未证明交易所逐笔完整性 | 近期数据补充与采集验证 |
| MaiRui 扩展基础/Pro | 历史 K 线、分析数据和因子接口；Pro 提供 1 分钟与完整历史分钟 API | 权限分层；不同接口历史长度与更新频率不同；财务 PIT/退市历史池完整性尚待核验 | 可继续作为低成本行情主源候选，不应因逐笔短历史否定整个厂商 |
| AKShare 等公开来源 | 开源采集工具，可组合日线、财务、事件来源 | 不是统一数据库或服务承诺；逐接口核实可用性、历史长度与字段口径；不能保证多年完整逐笔 | 免费原型与交叉核对，维护成本需计入 |
| Tushare Pro | 复权因子、证券上市退市信息、历史 ST 和财务公告字段，适合日频研究基础 | 积分/独立权限；财务公告字段仍需项目实现历史可见查询和修订管理；不是免费全功能或完整高频的保证 | 与行情源互补，优先评估历史状态/财务缺口 |
| RQData | 日/分钟/Tick、实时数据及显式 PIT 财务 API；统一接口有利于减少语义整合 | 商用，具体品种起始日期与套餐需验证；行情 Tick 不等同完整成交/委托逐笔 | 数据质量与研究规模要求提高后的商用候选 |
| 授权 Level-2 数据 + 券商接口 | 历史微观结构与真实执行分别补齐 | 成本、权限、历史深度及链路质量须单独验收；行情商不能代替订单通道 | 需要订单流/队列策略或真实执行时使用 |

MaiRui 官方因子文档明确部分北向字段暂按设计返回空。因此“列出字段”不能算成该数据完整可用；财务因子接口若不能还原当时可得值，也不能直接拿最新值回填历史。

## 不同策略的支撑比较

| 策略 | 当前项目 | 补齐日频基础和交易状态后 | 加分钟与 PIT 财务后 | 加授权 L2 与执行数据后 |
| --- | --- | --- | --- | --- |
| 日频趋势/动量 | 数据链路演示，历史不足 | 可开展可信度验收 | 能进一步改善执行评估 | 非必需 |
| 价值/质量/多因子 | 不足 | 仍缺财务历史可见性 | 可开展，需统一历史池/行业/复权 | 非必需 |
| 分钟日内策略 | 可看近期派生 Bar，未证明真实回测 | 不足 | 可开展分钟研究；撮合和成本另验收 | 更细执行评估 |
| 订单流/队列策略 | 不足 | 不足 | 快照或 K 线仍不足 | 数据条件可能满足，须验证完整序列与真实链路 |
| 自动实盘 | 未就绪 | 未就绪 | 历史数据充足也不等于实盘就绪 | 仍须真实 Broker、风控与订单/持仓对账验收 |

“可开展”均以真实策略执行、数据质量和费用/滑点/交易规则验收为前提，不表示能够盈利。

## 建议推进顺序

1. 先形成日频研究基础包：主数据与历史股票池、日线、复权/公司行为、交易状态、历史行业与基准。优先核验现有 MaiRui 权限，并用公开源交叉检查；发现明确缺口再评估补充来源。
2. 接入指定范围分钟行情下载，支持普通分钟与有权限的 Pro；分别显示来源最早日期、更新时间、账号权限及范围实际覆盖，不能误标为 Tick。
3. 为财务和分类数据实现按历史时点查询，保留公告、更正和采集版本。明确基本面策略需要时优先级升至 P0。
4. 先跑通真实策略回测和 Paper，再接实时行情及券商回报；高频 L2 与非结构化新闻根据策略目标后置。
5. 数据质量报告同时给出应有/实际证券数与证券交易日覆盖，缺档/休市/停牌/未归档分项、异常字段、对账差异及来源版本。对逐笔仅在有独立参考时声明完整，否则标“未证实”。

首轮验收样本需包含多个市场和板块、退市证券、历史 ST、停牌、新股、分红送转、历史成分变更及财报更正。Bar 区间覆盖以应有交易日与真实交易状态计算，不能用“每分钟必有一根”虚构无成交 Bar。质量未达标的数据集不得展示“可用于回测”；冻结版本后修复生成新版本，不静默覆盖研究输入。
