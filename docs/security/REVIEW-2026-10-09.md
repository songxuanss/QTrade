# Security and architecture review — 2026-10-09

This review covers the current repository and deployed local verification environment.
It does not certify unconnected broker integrations, unfinished Paper execution, a
production TLS deployment, or external email/webhook delivery. Those acceptance tasks
remain open in OpenSpec. The review's deployment acceptance is recorded in
`docs/testing/END-TO-END.md`.

## Closed priority findings

| Finding | Evidence and correction |
| --- | --- |
| Detached strategy descendants survived execution | A real Unix-socket execution forked, called `setsid()`, closed its standard descriptors and slept after the parent returned. The descendant was confirmed alive in the isolated container and explicitly cleaned up. Runner now adopts orphan descendants, allocates an unused per-job UID, kills all job-owned processes through pidfds, and reaps them before returning. Cleanup failure terminates the runner container rather than accept another job. The same real-container regression confirms the descendant no longer exists. |
| Web configuration errors left a running process | Real production-mode startup demonstrated Next instrumentation failure without process exit. The startup hook now emits only a safe configuration classification and exits. Actual process startup with missing protected secrets fails before readiness. |
| A recorded image ID became unavailable after rebuilding `latest` | The first actual rollback preflight refused the missing images before stopping the API. Release recording now creates independent retained tags. A later rebuild preserved them, and the real local rollback restored the prior five images with unchanged database row hashes. |

## Reviewed boundaries

- **Dependencies:** automated architecture checks and all architecture tests pass.
  Contracts/domain/application have no vendor SDK imports. SDKs remain in adapters,
  process composition remains separate, and the runtime package has no business imports.
- **Database queries:** variable column names are composed as quoted psycopg identifiers;
  conditional SQL clauses come only from fixed server templates. All user values remain
  bound parameters. The complete actual PostgreSQL suite passes, including cross-tenant
  isolation, membership revocation, idempotency, and concurrency/transaction checks.
- **Secrets:** protected startup uses owner-only mounted JSON, rejects symlinks and public
  file permissions, validates key material and public HTTPS addresses, and rejects
  development defaults and Live enablement without a real adapter. `.env`, `.tools/` and
  secret JSON are excluded from Git and images. A scan found no currently configured
  private values in tracked files, Git history or verification process logs. This is a
  configured-value scan, not proof that every possible unknown secret has been detected.
- **Logs and tracing:** request labels use route templates; SDK exports omit arbitrary
  attributes/events, bodies, SQL values, URLs and strategy output. JSON logs redact known
  configured secrets and URLs and retain exception classifications rather than exception
  payloads. Runner reapplies its formatter after Uvicorn config installs handlers.
- **Session/authorization:** real SSO browser checks and PostgreSQL tests cover membership
  restrictions, forbidden writes, audit/export denial and tenant isolation. Browser
  fixtures separately cover invalid signature/state, PKCE, cookie privacy, CSRF and
  logout replay. Fixture results are not called live SSO integration evidence.
- **Sandbox:** the deployed runner has no network, a read-only root, a private bounded
  tmpfs, CPU/memory/PID limits and no privilege escalation. User code receives a separate
  UID/GID and a minimal environment. Actual tests cover UID/GID drop, filesystem/network
  rejection, timeout, CPU/memory/output limits, responsive health, and detached descendant
  cleanup. The non-root library tests alone are not the isolation boundary; untrusted
  production code must use the configured container and Unix-socket service.
- **Socket/files:** four narrowly documented Bandit exceptions retain necessary traversal
  and worker-group socket permissions. Job directories are random, root-owned, cannot be
  listed/written by job users, and code files are group-readable without write permission.
  The socket permits the worker group; API has no socket mount and job GIDs differ.
  These are explicit boundary decisions, not a global scanner exclusion.
- **Immutable state/audit:** database tests prove append-only audit and immutable artifacts,
  checksums, tenant-scoped audit queries, field allowlisting, masked IPs and export limits.
  Full trading-event audit coverage remains a separate delivery requirement.
