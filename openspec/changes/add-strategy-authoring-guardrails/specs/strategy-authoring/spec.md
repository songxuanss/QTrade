# 策略创作

## Purpose

让用户在不知道策略接口细节的情况下，也能快速得到可运行、可校验、可回测的策略版本。

## ADDED Requirements

### Requirement: 官方模板库

工作台 MUST 提供至少二十一个官方策略模板，按趋势、反转、横截面、扫地僧与基准分组，覆盖均线交叉、时序动量、通道突破、MACD、ATR 止损、区间新高、RSI 均值回归、布林带、RSI 趋势过滤、横截面动量、双动量、波动率目标、横截面低波、横截面短期反转、龙回头、量价齐升、均线粘合突破、跳空不补、网格低吸、KDJ 金叉与等权基准。每个模板 MUST 同时提供可运行源码与参数 schema，并允许用户一键填充后继续编辑。多标的模板 MUST 逐标的维护独立状态，不得让不同标的共享同一组标量缓存。

「扫地僧」分组 MUST 只收录来自公开社区讨论、逻辑简单但换手较高的实战规则，并在界面标注其未经严谨学术检验，默认参数不构成策略有效性结论。

#### Scenario: 从模板创建策略
- **WHEN** 用户在新建策略时选择一个模板
- **THEN** 编辑器填入该模板源码，参数 schema 与参数表单同步更新，策略名称得到可编辑的默认值

#### Scenario: 模板源码可执行
- **WHEN** 仓库测试读取模板清单
- **THEN** 每个模板源码通过服务端静态校验，参数 schema 通过规范化校验，清单与生成器输出逐字一致

#### Scenario: 多标的状态隔离
- **WHEN** 在多标的日线数据集上运行任一多标的模板
- **THEN** 每个标的独立累计收盘价、指标与持仓数量，订单数量不随标的数量线性膨胀

### Requirement: 参数 schema 表单编辑

工作台 MUST 允许以表单维护参数名、类型、默认值、范围、枚举、必填与说明，并 MUST 保留 JSON 视图用于查看与高级编辑。两种视图 MUST 产出同一份规范化 schema。

#### Scenario: 表单新增参数
- **WHEN** 用户新增一个整数参数并设置默认值与最小/最大值
- **THEN** JSON 视图出现对应属性，回测表单可以渲染该参数

#### Scenario: JSON 解析失败
- **WHEN** 用户在 JSON 视图输入非法 JSON 并切回表单
- **THEN** 界面保留原文并提示错误，不静默清空或覆盖用户输入

### Requirement: 编辑器接口提示

编辑器 MUST 为 `qtrade` 策略接口提供补全与悬停说明，覆盖 `Strategy`、`on_start`、`on_bar`、`order`、`buy`、`sell`、`parameters` 与常用 bar 字段。提示 MUST NOT 替代服务端校验。

#### Scenario: 查询下单方法
- **WHEN** 用户将光标停在 `buy` 或 `order` 上
- **THEN** 显示方法签名、数量与订单类型约束

### Requirement: 内联静态诊断

静态校验 MUST 将诊断按行内联到编辑器，并保留列表视图。代码变更或重新校验时 MUST 清除过期标记。

#### Scenario: 校验发现禁止能力
- **WHEN** 用户在策略中调用被禁止的能力
- **THEN** 对应行出现错误标记，列表显示诊断码与说明

### Requirement: 执行语义不变

模板与表单编辑 MUST NOT 改变策略执行方式。保存后的版本仍为不可变 Strategy Version，仍只能由隔离 Runner 执行；模板元数据 MUST NOT 参与运行时或 manifest 复现判断。由于隔离 Runner 以标准库模式（`python -I -S`）运行，回测创建 MUST 明确拒绝声明了第三方依赖（`dependencies` 非空）的策略版本，而不是入队后在运行时以不透明的 `rejected` 失败；策略工作台 MUST 披露该标准库限制，并在校验通过后支持携带 `strategy_id` 与 `version` 直达回测实验页。

#### Scenario: 模板策略回测
- **WHEN** 用户用模板创建并校验策略后提交回测
- **THEN** 系统按既有冻结源码、参数与数据集执行，并生成同样的 manifest 字段

#### Scenario: 拒绝含第三方依赖的策略版本回测
- **WHEN** 用户为声明了第三方依赖的策略版本提交回测
- **THEN** 服务端在入队前以 `unsupported` 拒绝请求，不创建必然失败的排队运行
