# Design: 股票池采集与可迁移数据模块

## Context

单标的采集已有来源能力校验、重复/补缺计划、七天分段、Worker 与不可变原始批次及数据集。市场图表已按实际发布周期选择默认值。但当前 DataManagementService 直接持有 HistoricalIngestionWorker，并使用 QTrade WorkspaceAccess；市场视图枚举最近 200 个数据集，自选最多 50 个。仅增加批量按钮会放大耦合及遗漏数据问题。

用户要求重点支持采集和市场终端，采集将来可能迁入独立项目。本变更为设计，以下均为目标行为，不声称已经实施。

## Goals / Non-Goals

目标：快速按股票池采集、可靠看到每股结果、清晰区分原始采集/标准化发布/质量核验；采集迁移后保持 QTrade 用户流程和冻结研究引用稳定。首期 A 股，以日线为基础。

非目标：本变更不接通交易，不完成原变更回测/Paper/Live；不以当前概念成分构造历史有效成员，不根据供应商标签断言真实供货关系，不将未复权行情当成已核验复权收益。

## Decisions

### 1. 产品入口与股票池

采集页面有「快捷采集」「采集运行」「数据覆盖」三个视图。快捷区展示精简卡片，卡片先展开成员和范围预览，不在首次点击时创建大量任务。

| 入口 | 定义及交互 | 首期建议 |
| --- | --- | --- |
| 重点自选 | 个人自选、粘贴多代码、保存自定义股票池；不能冠以系统推荐股票 | 首批交付 |
| 指数 | 沪深300、中证500、中证1000、上证50、创业板指等候选；分开「指数行情」和「成分股」 | 有来源验收的入口才启用 |
| 大市值 | Top 50/100，可切换来源总市值/流通市值，预览排名与估值日期 | 全量排名输入通过验收后启用 |
| 行业 | 来源行业树、分类版本及成员，支持搜索与全选/取消单股 | 首批交付 |
| AI 供应链 | 芯片与算力、服务器、光模块/网络、PCB、存储、散热/电源、软件应用 | 版本化主题映射，允许多标签 |
| 芯片 | 设计、制造、设备、材料、封测 | 与行业分类并列，展示来源及归类依据 |

AI/芯片为主题观察池，每个子主题绑定明确供应商概念代码或有证据的人工规则，成员保存多个归属；不按股票名字或生成模型猜测。没有实际成员来源的卡片展示「来源未接入」，不虚构示例名单。当前成分只能回答“当前有哪些”，不能回答“历史上有哪些”。

市值排名必须冻结完整输入范围、字段单位、价格/股本时点、来源及筛选规则，提供全股票池与排除 ST/新股等选择；缺字段单独报告，不当作零。不同来源总市值、A股市值、流通市值、自由流通市值不得混排；首期采用来源明确的总市值和流通市值并标注口径。沪深与北交所覆盖分别显示，不能用仅沪深的输入宣称全 A 股排名。

### 2. 快速采集流程

选择股票池 → 预览成员和来源日期 → 选择周期与范围 → 查看已有/缺失/不支持情况及预计任务量 → 提交 → 聚合进度 → 打开市场终端。

默认「日线、截至最近已结束交易日的近一年、仅补缺」，范围可改；近一年是产品默认值，不是来源历史上限。提交时冻结股票池版本、具体成员、来源授权、周期、半开区间、补缺策略和转换版本。预览展示涉及股票数量、可复用范围、待采集分段数量与估计体量；估算不得冒充来源精确限额。分钟/Tick 按能力与权限呈现，Tick 另显示尚需发布分钟数据的条件。

多股票/多主题先按统一标识去重，归属仍保留。每股范围继续七天分段；部分失败允许仅重试失败或缺失，重新下载全部仍显式可选。预览计划有有效期和版本：成员变化不影响已冻结版本；覆盖变化导致版本冲突时刷新计划并展示变化，不默默改成全量下载。

### 3. 领域划分与数据所有权

数据模块包含参考数据、采集和标准化发布/查询三个内部模块，首期可共用进程，接口分开。它拥有股票池快照、来源能力、采集计划/运行/子任务、原始归档、覆盖、数据集清单、标准行情和质量报告。QTrade 拥有用户界面、个人自选偏好、策略、回测、交易、组合与交易风险。

采集领域不导入 QTrade 的 WorkspaceAccess、策略或交易对象。外部请求仅传通用 scope_id、actor_id、授权动作、关联标识及冻结数据选择。QTrade BFF 验证用户与当前工作区后转换；采集入口仍独立验证 scope/action，不相信浏览器传入的身份。QTrade 权限变化通过授权适配器在提交及敏感控制时生效，Worker 通过当前来源授权检查执行。长期运行不把一次会话或长时有效签名当成永久权限。

引用只使用稳定标识和版本，不使用 QTrade 业务表外键、共享 ORM 或跨模块 SQL。即使同一数据库实例，也由各自迁移和数据库角色管理独立 schema。独立运行配置不需要策略数据库、交易账户或 QTrade 私有会话。已有标识保留；迁移清单包含旧 workspace_id 到 scope_id 映射，不能改写历史数据集和回测引用。

参考主数据须区分股票、指数和主题标识。上证指数与同数字股票代码不得冲突；接口返回 instrument_kind 与统一身份，适配器维护来源代码映射。指数不是可交易股票，不套用股票 lot-size/下单模型，主题聚合曲线也不能冒充官方指数。

### 4. 对外接口与迁移路径

三个稳定的外部 Interface：

- UniverseCatalog：查询/解析股票池，返回带版本的成员快照、来源、日期与分类；支持分页，不向调用方暴露来源概念接口。
- CollectionGateway：查询能力、创建预览计划、提交幂等运行、读取进度、重试或取消未执行工作；调用方不负责拆段/限流/来源游标。
- MarketDataCatalog：按标的和周期查询覆盖/数据集、读取不可变清单/质量报告、分页查询标准 Bar；调用方不枚举所有采集任务来猜数据是否存在。

DTO 只含 JSON 基础类型、UTC 时间、明确单位与字符串精确数值，具有 schema_version；标识、错误分类、游标、幂等、权限和一致性保证也是契约的一部分。凭证只用服务内部引用，不出现在 DTO 或来源 URL。HTTP v1 是独立部署传输，首期同进程 Adapter 与远程 HTTP Adapter 在同一契约测试下比较。

QTrade 市场终端经消费 Adapter 接口读取，禁止导入采集 Worker 或直接读取采集私有表。数据模块迁出后替换消费 Adapter 和地址/服务认证配置，不要求改写策略、回测或市场组件。采用独立数据存储模式优先于复制所有行情到 QTrade；大文件使用受授权短期访问与校验和，不在事件中传大段行情。

先在同仓库分离领域/包和 composition root，再提供独立入口/配置/迁移/最小发行包，再在隔离数据库中运行，并用 QTrade 远程 Adapter 验收。独立发行不得安装整个 qtrade_domain 大包从而间接引入交易领域。迁移演练必须包含原始文件、对象清单、质量报告、ID 映射与校验和，而非只复制任务记录。

### 5. 聚合运行、一致性与恢复

Collection Campaign 是冻结采集选择与结果的聚合运行，不替代 Data Batch 或 Market Dataset。事务先持久化运行、冻结计划和待展开工作；大量子任务分分页幂等展开，用稳定身份和唯一约束防止重启重复。页面同时显示计划数/已展开数，不能因为只生成部分任务而显示整体完成；既有单标的原子七天提交保持兼容。

运行状态包括等待、执行、部分完成、完成、失败、取消；取消保留已写入的不可变产物，仅停止未开始工作和安全检查点后的继续执行。每股和每段分别记录采集结果和发布结果。空响应为「无观测数据/待核验」，权限拒绝、限流、来源异常分类可见；非空原始归档和非空标准行情可查询才显示「可查看」。单个已采集任务不能证明全池已完成或研究就绪。

来源 Adapter 内控制来源级并发/请求额度和退避；首期并发默认 2，可配置，实际订阅限额来自能力配置和错误反馈。聚合取消、部分失败与恢复不重写成功批次。审计为模块本地追加事实，QTrade 通过事件投影读取，不能把写入 QTrade 审计表作为采集提交成功的必要步骤。

状态事务与 outbox 同时提交；事件包含 event_id、scope_id、aggregate_id、递增版本、correlation_id、发生时间、清单引用，不含凭证。至少一次投递，消费端去重、按版本防倒退。通知只刷新视图，数据目录和运行查询是真实状态来源；游标补拉与定期核对修复断线/遗漏，事件不可用时查询仍工作。发布事件不能早于标准行情及清单的持久化提交，且存储失败不会先发成功。

### 6. 市场终端与专业 UI

左侧股票池导航，中部带分页/排序的成员表，右侧或下方 K 线详情；手机用股票池选择器、精简列表和独立图表区域。个人自选保持轻量，完整指数不自动加入最多 50 个自选。

表格显示名称、代码、来源主题、市值口径/日期、最近已发布价格/日期、可用周期、覆盖范围和缺口状态。默认按可用行情选择周期，采集结果链接带确切标的/周期/快照。无数据行提供创建补缺计划入口；实时源未接入时明确「最近已发布行情」，不使用暗示盘中即时的标签。

完整股票池采用服务端稳定排序和分页，覆盖查询按标的/周期索引及分页清单返回，不能只检查最近 200 个数据集。相对基准比较仅在有同日期、明确复权口径及可用指数数据时显示；自编等权池收益标注公式、成员快照和质量，不叫官方指数。首期优先成员表、覆盖和单股 K 线，热力图与主题曲线后续再做。

聚合进度条配「已采集 X/Y、可查看 A/Y、失败 B」和逐股展开；缺失/未核验/失败不能共用“成功”绿色标签。页面统一间距、排版和状态色，有加载/空/失败状态，键盘可操作，手机无横向溢出。

## Sources and Unverified Assumptions

- [Mairui 沪深文档](https://www.mairuiapi.com/hsdata)：板块树 `/hszg/list/{licence}`、成分 `/hszg/gg/{code}/{licence}`，行情字段包含来源总/流通市值。须验证全量输入口径，不从涨停榜子集生成全市场 Top N。
- [官方行业概念示例](https://mairui.club/blog/python-concept-sector-stock-filter-20260721/)：目录解析、成分查询后批量拉日线，并提示并发/限额。
- [中证指数](https://www.csindex.com.cn/)：官方成分/编制信息作为指数来源候选，历史成员和指数行情需另外核验。

以上为文档调查，未调用当前证书实测这些新增接口，不把公开或免费文档视为授权、稳定性或完整性承诺。

## Risks / Trade-offs

独立 HTTP 首期会增加认证、运维和失败处理成本，因此先保留本地 Adapter；但禁止跨模块数据库访问，否则未来迁移成本不可控。维护当前股票池快照能复现下载选择，不能消除历史成员缺失带来的幸存者偏差。大池需要分页调度和存储容量预检，不能将无限范围等同于无限资源。

## Verification and Delivery Order

先交付独立契约和来源实测，再按自定义/行业/指数成分、市值、主题分批交付 UI。每批都跑部署 UI→权限→计划→Worker→真实来源→非空原始归档→标准数据→市场图表→刷新，并记录角色拒绝、来源拒绝、空响应、限流、重复、补缺、部分失败和重启恢复。桌面/手机同时验收。

迁移验收使用独立数据库/对象存储/Worker，无策略与交易包或库权限；QTrade 仅通过 HTTP 读取相同结果。用同进程/远程契约测试比对错误、作用域和数据哈希，测试凭证撤销、跨 scope 拒绝、重复/乱序事件及通知丢失后的恢复。未完成迁移演练或实际来源的入口保持未验收，不勾选完成。

## Concrete Acceptance Example

用户选择「芯片 → 设备与材料」的已验收当前快照，预览实际成员并取消个别股票，
选择近一年日线和仅补缺。系统展示实际股票数、已有覆盖与缺失分段，提交时冻结
快照。两主题有重合股票只采一次；一年每股会产生多段，但市场视图合并同周期
已发布数据，不要求用户逐段打开。某股失败时运行显示部分完成、成功股可立即
看 K 线，失败股可单独重试。刷新保持状态，手机打开成功股直接是日线。迁移
到独立数据服务后，相同快照与产物 ID 仍可从市场终端读取。此为验收设计示例，
不提供未经来源实测的具体股票名单或冒充已完成执行。
