# Spec Delta

## Purpose

让用户在专业量化工作台中清楚配置、预览和启动采集，并独立查看任务执行、历史记录及已发布数据，同时保持权限和结果状态真实可辨。

## ADDED Requirements

### Requirement: 采集工作流分区
采集页面 MUST 将任务创建、执行监控和结果查看组织为可辨识的区域，创建步骤按数据类型、来源与周期、标的、日期和下载方式的顺序呈现。

#### Scenario: 首次创建行情采集计划
- **WHEN** 有管理权限的用户打开数据管理页
- **THEN** 页面明确显示行情/因子类型、来源、周期、标的或保存股票池、日期、下载方式与计划预览入口，任务历史和结果不会打断创建顺序

### Requirement: 预览后确认提交
页面 MUST 将计划预览与创建任务分为两个明确步骤，并在预览区显示冻结标的、日期范围、来源、周期、已完成/处理中/缺失数量和补缺或全量语义。

#### Scenario: 用户确认批量股票池计划
- **WHEN** 用户选择保存的股票池并生成预览
- **THEN** 用户可以先检查去重标的和计划数量，再明确提交；预览前不会创建任务

### Requirement: 单标的与板块批量入口清晰区分
页面 MUST 明确区分单标的/因子采集和股票池全成员批量采集，并在批量流程中展示其默认周期、日期范围与下载方式。

#### Scenario: 用户从板块卡片下载全部成员
- **WHEN** 用户进入板块批量计划
- **THEN** 周期默认日线、范围默认近一年、下载方式默认仅补缺，并可在预览前修改；单标的采集面板的周期选择不改变批量默认值

### Requirement: 任务状态与产物分离呈现
页面 MUST 在独立任务区域展示最近任务、所选任务总体状态、分段进度、失败原因和重试/取消操作，并把已发布记录与市场终端可见状态单独标识。

#### Scenario: 批量任务部分失败
- **WHEN** 任务含已发布、失败或无观测分段
- **THEN** 每种结果均可区分，用户可定位失败分段和重试，已发布行情提供对应标的与周期的图表入口

### Requirement: 响应式和只读布局
工作台 MUST 在桌面与窄屏保持明确阅读顺序、可操作控件和状态可见；页面提供任务分区快捷跳转，只读角色可查看任务与结果，但不能看到可提交的采集表单。

#### Scenario: 手机查看任务与历史记录
- **WHEN** 用户在窄屏打开工作台并切换到最近任务
- **THEN** 配置、状态、操作和记录表按单列阅读，页面没有非预期横向溢出，宽表格可在自身容器内滚动

#### Scenario: 从页面目录跳转到板块任务
- **WHEN** 用户从数据管理页顶部选择板块批量采集
- **THEN** 页面定位到独立的板块任务区域，其默认值和确认操作可见，其他旧任务记录不挤占该配置区
