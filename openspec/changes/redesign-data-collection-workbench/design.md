# Design

## Context

See `proposal.md` for motivation. 现有 `CollectorPanel` 是包含表单、预览、任务历史、状态、分段和数据表的单一客户端模块，样式以通用四列网格为主。`DataWorkbench` 同时呈现独立采集、股票池批量下载、旧版 Tick/历史表单、任务、批次及质量记录；股票池下载另有独立的 `CampaignPanel`，默认日线、近一年、仅补缺。

专业平台参考：TradingView 将图表工作区和 watchlist 分开并允许按工作流切换布局；QuantConnect 将数据集、研究和运行结果分层呈现。本设计据此保持配置、执行与结果的视觉分区，而不复制其产品功能。[TradingView 布局](https://www.tradingview.com/support/solutions/43000746975-tradingview-layouts-a-quick-guide/)；[QuantConnect Research Environment](https://www.quantconnect.com/docs/v2/research-environment)。

## Goals / Non-Goals

**Goals:** 让单标的/因子与板块批量采集一眼可区分；在桌面端减少长表单的扫描负担；提供页面级分区导航；让任务状态和结果可单独定位；小屏下维持线性阅读和键盘可达性。

**Non-Goals:** 不改 API 与表单字段语义，不重写数据管理整页，不增加图表或监控指标，不改授权和下载规则。

## Decisions

- 保留 `CollectorPanel` 作为一个有状态模块，内部划分为创建、计划、任务和产物区域，避免拆散共享的权限与任务状态。
- 在页面顶部提供对应锚点的轻量目录，将单标的/因子、板块批量、采集任务、原始批次和质量问题分开定位；旧逐笔和兼容历史入口保留原功能。
- 将 `CampaignPanel` 视觉上独立成批量下载卡片，明确它默认日线/近一年/仅补缺，且不读取或继承 `CollectorPanel` 的分钟周期。
- 创建区用分组卡片和两栏网格：主列放数据范围/标的，辅助列放计划设置与摘要；预览仍在提交前原位出现。
- 任务状态设为明显独立的执行区，最新任务详情优先显示；最近任务列表折叠且可展开。产物预览作为任务区下方的独立数据浏览区。
- 行情与因子使用有清晰选中态的类型切换控件；周期仍按来源能力渲染，默认仍为当前的 5 分钟周期。
- 使用现有 CSS 变量与原生控件，不加组件库；移动布局改为单列，表格仅在自身滚动容器内横向滚动。

## Risks / Trade-offs

- [任务区域增加分组后页面仍可能偏长] → 默认折叠非当前任务的历史列表，当前运行状态保持可见。
- [双采集入口仍可能让用户混淆默认周期] → 顶部导航与板块下载卡片分别标注单标的周期选择和批量默认日线。
- [新视觉结构导致现有自动化选择器失效] → 保留表单 `aria-label`、关键按钮文本、任务/产物 data 属性，使用现有真实 SSO UI 流程检查。
- [小屏中任务卡片信息密集] → 状态和标的名称优先显示，技术 ID 与关联信息作为次级文本换行。

## Migration Plan

仅发布前端构建，无数据迁移。回退时恢复本变更涉及的前端文件；既有服务 API 和持久化任务不受影响。
