# Proposal

## Why

当前采集页把创建任务、预览计划、运行监控、历史任务和数据表格连续堆叠，用户难以判断先做什么、任务进行到哪一步。量化工作台需要把配置、执行和结果分成稳定区域，让批量采集与异常处理一眼可辨。

## What Changes

- 将采集入口组织为“创建采集、任务监控、数据预览”三个清晰区域。
- 按行情与因子区分采集类型，在桌面端使用配置区与计划摘要并列布局，在窄屏按流程纵向排列。
- 明确区分单股/因子采集与股票池批量下载入口；在批量入口标示默认日线、近一年、仅补缺。
- 将日期范围、标的/股票池、周期及补缺/全量模式归入有顺序的配置组；预览计划后再显式提交。
- 将最近任务收纳为可查阅的任务列表，运行详情、分段状态和产物检查集中呈现。
- 在页面顶部增加任务分区导航，快速跳转采集配置、板块下载、任务、归档与质量信息。
- 保持现有接口、权限、周期默认值、任务语义和市场终端导航不变。

## Capabilities

### New Capabilities
- `data-collection-workbench`: 数据采集工作台的信息层级、创建流程与响应式任务查看行为。

### Modified Capabilities

## Impact

- 前端：`apps/web/src/features/data/collector-panel.tsx`、`universe-panel.tsx`、`campaign-panel.tsx`、`workspace/data-workbench.tsx` 与 `apps/web/src/app/globals.css`。
- OpenSpec：新增采集工作台能力规格。
- 不改后端契约、任务状态、数据库、来源配置或行情数据。

## Non-Goals and Safety Boundaries

- 不改变采集范围、默认周期、补缺/全量语义、身份权限、来源授权或后台重试行为。
- 不将空数据、未发布行情或失败状态包装成成功；不增加任何交易或订单操作。
- 不新增前端依赖或对外服务。

## Assumptions

- “下载全部成员”仍从已冻结股票池提交；本次只整理其表单和结果位置，不更改该入口行为。
- 当前 API 返回的数据足以在界面展示来源、覆盖预览、任务状态和已发布产物。
