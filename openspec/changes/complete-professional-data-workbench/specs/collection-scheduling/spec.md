# 规格增量

## Purpose

为专业量化数据工作台提供可验证的collection-scheduling能力，明确用户操作、版本化数据、失败恢复及研究限制，确保独立采集服务和消费者通过公开契约协作，并以真实结果区分样本、受控验证与生产可用性。

## ADDED Requirements

### Requirement: 持久自动增量计划
系统 MUST 保存范围/冻结池、来源、类别、周期、时区、运行时间、启停和授权上下文，按交易日历及来源发布时间补缺；财务、事件和各因子采用自身更新规则。

#### Scenario: 日频触发
- **WHEN** 启用计划并到达应更新时间
- **THEN** 生成真实补缺运行，休市不误报故障，稀疏事件不套用价格每日完整性

#### Scenario: 启停与当前授权
- **WHEN** 停用计划或撤销主体/来源权限
- **THEN** 不创建新运行并记录原因，凭证不进入计划或浏览器

### Requirement: 恢复去重与有界补跑
调度及Worker MUST 通过持久运行身份、租约和有界补跑恢复；重复触发、重启、部分失败不破坏成功产物，全部状态须如实聚合。

#### Scenario: 重启与重复触发
- **WHEN** 调度或Worker停机后重启并重复触发相同周期
- **THEN** 有界补跑且同一运行身份不重复创建，成功产物保留

#### Scenario: 失败与取消
- **WHEN** 部分执行失败或用户取消
- **THEN** 区分等待、执行、部分成功、失败、取消、无观测和完成，重试仅失败部分

### Requirement: 有界修订复核
系统 MUST 支持配置范围与成本的迟到/修订复核；变化生成新版本并保留旧冻结引用，手工、定时及复核共用执行控制。

#### Scenario: 发现修订
- **WHEN** 有界复核观察到值或事件变更
- **THEN** 产生带血缘新版本，不覆盖旧研究引用并显示复核成本
