# 规格增量

## Purpose

为专业量化数据工作台提供可验证的research-record-lifecycle能力，明确用户操作、版本化数据、失败恢复及研究限制，确保独立采集服务和消费者通过公开契约协作，并以真实结果区分样本、受控验证与生产可用性。

## ADDED Requirements

### Requirement: 来源能力与证据
系统 MUST 提供市场、类别、周期、历史边界、单位、调整、更新、权限、配额、许可及证据等级目录；区分未配置、文档声明、样本验证与真实闭环。未知或未接通能力禁用且说明解阻条件。

#### Scenario: 目录与探查一致
- **WHEN** 查看来源能力
- **THEN** 实际样本、文档与未知项分别呈现，未接入不写成供应商不提供

#### Scenario: 逐项证据与配置分开
- **WHEN** 用户读取来源说明
- **THEN** 历史、单位、调整、时间、更新、权限、配额、许可分别记录证据等级、核对日期及文档引用，未知项给出确认条件；已配置不等于当前权益或全范围已验证，平台保护预算不冒充供应商套餐额度

#### Scenario: 证据修订不改写冻结计划
- **WHEN** 来源说明增加或纠正证据
- **THEN** 通过独立只读版本化契约公开，不改变已冻结计划、发布和研究引用的内容或摘要；读取不出站探测权限或下载，未接通类别只提供限制说明

#### Scenario: 当前成员与历史区间分开
- **WHEN** 用户查看当前参考目录的能力
- **THEN** 明确当前成员快照、观察时间和分类版本，不宣称历史生效区间、权重或历史日期查询；状态来自该目录部署自己的配置，不借下载服务配置证明可用

#### Scenario: 独立目录部分不可用
- **WHEN** 下载侧或参考侧来源说明无法读取
- **THEN** 保留另一侧实际可读的说明并明确缺失分组，不把局部目录称为全部；跨作用域或重复身份的组合拒绝，服务恢复后可刷新完整目录

### Requirement: 类型化研究记录
系统 MUST 提供版本化财务、成员有效区间、证券身份变更、公司行为关键日期及复权因子/基准/版本的明确类型；保留原值、单位、观测/报告/生效/披露/采集与可知时间证据，不把未知补成零或采集时间。

#### Scenario: 财务修订及未知时间
- **WHEN** 同报告期存在不同披露日或值
- **THEN** 分别保存版本，披露日期不自动作为精确可知时间，未知单位不进行暗中缩放

#### Scenario: 成员与事件
- **WHEN** 接入成员区间、身份变更或公司行为
- **THEN** 有效区间与观察时间分开；稳定事件身份和内容版本分开，重复事件幂等

#### Scenario: 复权语义
- **WHEN** 请求复权价格或因子
- **THEN** 明确区分价格、因子、基准和版本，复权价格不被解释为实际成交价格

### Requirement: 因子原值与定义版本
系统 MUST 同时保存因子供应商原值与标准值、身份、定义/计算版本、观测/采集时间及实际提供的报告/更新/可知时间；供应商和本地计算来源分开，区分未开放、无权限、无历史、合法空值及异常缺失。

#### Scenario: 原值和版本变化
- **WHEN** 来源更新定义或值为空
- **THEN** 旧版本不改写，原值与标准值可追踪，空值原因和缺失证据明确

### Requirement: 研究时点限制
系统 MUST 仅在版本及历史可知证据充分时启用按研究时点查询；普通历史财务、当前成员、部分公司行为及未知复权前提显示研究限制，采集成功不自动标回测就绪。

#### Scenario: 无PIT证据
- **WHEN** 普通财务仅提供披露日期并请求历史时点查询
- **THEN** 明确拒绝PIT查询并保留普通版本查询

#### Scenario: 受控修订隔离
- **WHEN** 有证据的受控数据在后续修订后查询早期时点
- **THEN** 返回当时可知版本，未知可知时间记录不被选入；证据标fixture不计供应商实接

### Requirement: 共享扩展生命周期
新增类别 MUST 经能力发现、计划、分页/游标获取、原始归档、标准化、质量、发布及查询的公共生命周期；契约拒绝未知版本及类型，不使用任意JSON或行情字段承载研究记录。

#### Scenario: 受控适配器验证
- **WHEN** 安装受控新增类别适配器并执行完整生命周期
- **THEN** 得到可校验不可变原始和标准产物及版本查询；迁移、成员区间、事件去重与未知时间通过契约测试且明确fixture
