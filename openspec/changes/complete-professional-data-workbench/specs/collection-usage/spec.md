# 规格增量

## Purpose

为专业量化数据工作台提供可验证的collection-usage能力，明确用户操作、版本化数据、失败恢复及研究限制，确保独立采集服务和消费者通过公开契约协作，并以真实结果区分样本、受控验证与生产可用性。

## ADDED Requirements

### Requirement: 估计与硬控制
系统 MUST 在预览显示任务量、调用估计区间及依据；配置来源/作用域并发、每日预算、单次规模及确认阈值，执行时原子重验。所有手工、重试、定时和复核共用预算，确认不能越过硬配额。

#### Scenario: 并发与配额拒绝
- **WHEN** 多个任务同时达到硬预算或规模上限
- **THEN** 执行不绕过预算，显示拒绝/等待原因且不发生越额调用

#### Scenario: 调用量估计
- **WHEN** 缓存、分页或空数据使成本不确定
- **THEN** 展示估计区间、加权信用依据与不确定性，不声称精确报价

### Requirement: 实际用量与公平性
系统 MUST 展示实际调用、重试、限流、队列等待和存储，领取遵循配置公平性，大任务不能长期饿死其他任务；日志可按关联ID定位且无凭证。

#### Scenario: 竞争与等待
- **WHEN** 大池与小任务同时运行
- **THEN** 按公平策略均得到进展，预算及等待可查询

#### Scenario: 诊断与安全
- **WHEN** 查询来源健康、积压和失败原因
- **THEN** 能定位阶段和重试，日志、报告、截图无秘密

### Requirement: 性能基线与恢复证据
交付 MUST 先记录明确环境小中大基线再定性能/恢复目标并复测，区分平台耗时与供应商等待；数据库、对象及manifest在隔离环境备份恢复后查询和UI一致。

#### Scenario: 性能验收
- **WHEN** 固定规模基线后设置目标并复测
- **THEN** 报告实测吞吐/资源/恢复且不外推全市场

#### Scenario: 隔离恢复
- **WHEN** 恢复本次范围备份到隔离环境
- **THEN** 摘要、记录、版本引用及UI查询一致，不在生产执行恢复
