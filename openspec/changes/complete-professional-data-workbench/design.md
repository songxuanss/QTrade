# 技术设计

## Context

动机见 proposal.md，原始验收要求及证据逐项见 docs/testing/COLLECTION-GOAL-COVERAGE.md。独立 collector 已有 contracts/core/供应商/PG/archive/HTTP 边界，当前只支持 v1 行情和因子；规划统一七天，发布只有基础转换检查，尚无持久调度、预算、新鲜度及研究类型。实际用户验证入口是 13000 Web → 3122 已持久化认证 API → 18100 独立采集，身份服务 3121；不能用未接认证的 18000 默认 API 替换并丢失现有业务状态。

来源证据见 docs/data/CAPABILITY-AUDIT-2026-10-12.md。财务多披露版本已实测，不具备完整 PIT 证据；前复权早年负价格真实存在；元数据缺单位/计算版本，不能由文档示例伪造响应字段。

## Goals / Non-Goals

设计以独立采集生命周期为深模块，QTrade 只负责认证代理、消费及告警桥接，不导入采集内部实现或读取其表。计划、预算、质量和时间规则以明确领域值和端口表达，基础设施可替换。保持已有 v1 不可变产物兼容，新类型明确版本并存。

不建立任意插件平台；不从普通披露日期推导无前视研究能力；不接实盘订单。采集产物与消费者导入分别验收。

## Decisions

### 1. 固定接入范围与证据边界

现有 MaiRui 授权下，必接入未复权 A 股日线、Pro 1m/5m、用户明确选择的历史因子，普通历史 balance/income/cashflow 三表和有限现金分红/送转事件。核心真实验收证券为 600519.SH、601288.SH，当前沪深300及自建池用于冻结范围；日线和 pe_ttm/roe_ttm 覆盖默认自然年、指定范围及增量，north_holding_ratio 用于最新/历史空响应差异验证。分钟用 2025-09 指定区间和跨年度计划验证，不由一个样本承诺全上市期。财务选择 2015/2025 报告区间，验证同报告期多披露版本；事件验证正送转、日期、每十股单位及未知支付日。

未知财务单位保留原值与显式 unknown，累计语义标来源待确认，不进行隐式缩放/单季差分。普通历史浏览和版本查询可用，PIT 查询禁用。当前成员仅快照；历史有效成员、退市/身份变更、完整配股拆并股和复权因子/基准通过明确类型及受控适配器验证，不提供虚构 live 入口。f/b 价格样本及负价格风险公开展示，本次不将其直接接为研究就绪价格。这样保留已验证有限能力，优于统一推迟所有研究数据，也优于从部分字段宣称完整体系。

### 2. 生命周期与版本化契约

扩展 v2 类型化 tagged union：FinancialStatement（报告期、披露日期精度、可知证据、声明期间语义、typed metric/decimal/unknown单位、来源版本与内容版本）、MembershipInterval、SecurityIdentityChange、CorporateAction（稳定事件身份、公告/登记/除权/支付/上市等各自可空日期）、AdjustmentFactor（口径、基准、算法版本）、FactorObservation/Definition。

不修改旧 v1 manifest 哈希。新版本发布记录携带 raw/standard 摘要、转换和规则版本、原始来源值、采集时间、质量状态与研究限制；分页/游标范围与内容版本稳定。版本查询必须显式引用；as-of 只选有可知证据版本，未知时间不以采集时间回填。v1 和 v2 分别解析并拒绝未知 schema，不依赖 arbitrary JSON 标准记录。

ProviderPort 提供能力发现、计划边界、获取页/游标及标准化，ArchivePort 在标准化和门禁前保存不可变原始批次，RepositoryPort 管理租约/质量运行/发布状态。消费者只有已发布公共接口。受控适配器覆盖每种新增类型生命周期；仅 fixture 证据，不能升级供应商状态。

### 3. 来源感知规划

规划策略按来源与类别设置，Provider 声明时间/条数/分页边界，配置可收紧，不能超过硬接口限制。Pro 往年分钟按市场年边界，复用带摘要年片缓存；当前年接口按分页能力，因子不超过声明点数并对响应日期/排序/分页核验；日线按已验证接口能力。总时间默认无限制；所有范围统一半开UTC且保留市场时区。已有冻结子任务不迁移、不重新编号，只有新计划用新策略版本。

以显式策略值注入规划核心，优于核心识别供应商名称或统一七天。预览和执行采用同一计划及覆盖版本；占用仅包含真实成功覆盖及有效在执行范围，空响应不算价格覆盖。

### 4. 工作台与持久选择

UI 分选择、范围、计划、执行、结果，默认日线/一年/补缺。显式标的优先于池，无标的才冻结池；明确日期/来源/周期不被自动替换。默认结束从市场日历、来源完整时段和发布时间计算，不读本地最大日期。输入保存在作用域和用户隔离的偏好记录，运行请求幂等键与预览版本绑定；重复点击返回原运行。

因子多选按分类搜索；未知字段及仅最新历史差异就地显示。取消和重试由任务状态机处理，保留成功部分。目录采用持久最近可用快照与后台刷新，页面不等待每次上游元数据网络请求。断网仍能查询旧任务，错误说明恢复操作。专业桌面布局和手机局部滚动/键盘反馈维持。

### 5. 调度与当前授权

持久 Schedule 包含冻结范围、类别更新策略、时区、当地运行时间、启停、授权主体/作用域及最大补跑窗口，无凭证。每次执行重新调用 Authorizer 和来源权限；失效暂停并记录原因。ScheduleRun 身份由计划版本与应运行时刻确定，数据库唯一约束去重。交易日历/发布规则通过 Provider CalendarPort，不按简单周一到周五猜测。

持久基础新增独立contracts/core/PG schedules模块与0014追加迁移，不复用QTrade的calendar_schedule日历修订表。严格选择区分market行情/因子与research类别，冻结标的/成员快照引用、显式因子、cadence/local time/IANA、lookback/catchup及批准规模信用；automation_confirmed必须明确布尔true，无凭证字段。cadence是操作意图，不是来源更新时间证据，创建默认disabled。

PG短事务领取SKIP LOCKED及token/expiry/revision fencing，重复enable不改有效所有权，disable原子清除lease，旧/过期owner不能advance。run reservation由schedule UUID、完整revision、UTC规范due_at派生UUID，唯一槽及DB不可变触发器保证恢复后同身份；reservation不是任务/下载成功。当前核心控制只提供授权创建/读/停用，未暴露启用HTTP/UI、未连接timer或来源执行；来源/日历发布策略、当前执行授权、预算/确认和有界补跑必须下一阶段接入，7.1不因此完成。

调度领取与Worker均使用持久租约和 fencing token，停机后只补跑配置窗口。迟到/修订复核独立 operation，记录边界成本，发现变化新增版本；冻结引用保持不变。稀疏财务/事件和周季因子使用类别策略，不能套行情缺日规则。

统一schedule_clock按IANA时区计算操作节奏，首槽严格晚于创建，恢复包含当前槽并以连续24小时窗口有界扫描；DST缺失跳过、重复取首次，返回UTC以保持身份。季度首日/配置星期仅为操作意图，不代替来源更新规则。窗口前仅记省略界限，不伪造遗漏计数。保留运行前复核冻结主体当前manage；明确撤权在版本/token/数据库到期防护下持久暂停并清owner，授权unavailable拒绝保留但不误写撤权。尚无timer/source policy/UI自动运行，7.x未完成，证据见COLLECTION-SCHEDULE-STORE-2026-10-14.md。

PostgresScheduledJobs在既有JobRepository接口内绑定lease/run，不复制规划/Worker流程。来源预检完成后、写入之前，在同一job事务锁schedule行并复核当前enabled/revision/token/UTC槽与不可变run关联，使用clock_timestamp而非事务开始时固定的now判到期。冻结actor/source/category/period/fields/instruments及missing模式必须一致；禁止从无atomic连接直接插入。锁随任务提交事务结束，避免停用已确认后旧owner再插入；元数据HTTP期间不持schedule行锁。既有同请求只读幂等仍可返回，但不得重写成功产物。此adapter尚未装配timer/HTTP/UI，也不代表批准信用上限、持久请求范围/恢复日志及来源日历已接通；7.x保持未完成。

ScheduleExecutionApproval为内部严格草案派生的批准检查，不属于浏览器提交契约。行情/因子submit在普通硬规模/覆盖检查后，以事务内新预览核对冻结actor/scope/source/category/period/fields/标的及missing模式，再比较missing_parts和credits_max与批准上限。未知估计拒绝；超限抛ScheduleApprovalRequired，即使confirmed=true也不能绕过。有效批准可替代本次普通确认阈值的人工操作，不替代当前授权、最终租约准入和出站硬预算。已接受相同请求保持原幂等结果。信用批准约束无重试规划估计，非实际支付承诺；metadata/重试/跨运行实际调用仍由共享账本限制。当前只实现market批准，研究、超限暂停装配、恢复范围日志及timer/UI继续未完成。

恢复范围采用独立v1 ScheduleDispatchDecision，discriminated market/research内嵌原v1 CollectionJobRequest或v2 ResearchPlanRequest，绑定scope/schedule/run/revision/UTC槽、policy版本/安全依据和首次freeze时间；mode只missing，request/correlation身份等于保留run。0015追加不可变日志表和NULL-safe身份/FK约束，不改既有迁移。当前主体授权和有效租约下freeze，锁取得后使用数据库实际时刻判到期；首次语义写入获胜，重复仅可有不同freeze候选时间，返回首次原摘要。范围、主体、来源、类别、policy或草案revision变化冲突，不覆盖旧日志。读者当前read且scoped读取，核对摘要及canonical保留槽关联。最终market入队必须有日志且request完全一致，缺失/损坏拒绝。日志只证明输入，不是任务成功；timer/source eligibility/研究准入和真实自动UI仍未接通，7.x不因此完成。

ScheduleRunner每次仅处理一份持久lease：当前主体授权、有界窗口推进或保留槽、优先原日志、必要时Policy准备并冻结、普通预览/批准/事务准入、最后推进下一槽。提交与推进之间失联时，重领后复用原请求并幂等提交；submitted是入队而非下载完成。明确撤权、来源错误和超批准分别fenced暂停；预算拒绝/冲突deferred，原lease可重领，不出站绕预算。日线Policy通过既有Provider日历/预计发布时间，只有相邻cadence槽间有新预计发布才采集；半开回看按市场本地日期，休市正常skip，周频操作可在周日采周五。不从日线推断因子/研究频率，未知策略拒绝暂停。普通Worker消费任务和发布，独立async timer不阻塞手工Worker/元数据刷新。COLLECTOR_RUN_SCHEDULER默认true，interval默认2秒、范围1–60；仅enabled计划可领取，默认创建disabled。日志仅allowlisted scope/schedule/run/state/error。当前还没有启用HTTP/UI，因子/研究策略与真实重启/撤权全矩阵仍未完成，7.x不勾选。

正式/v1/schedules提供分页scope读、严格创建、版本绑定启停；创建/启用前核对当前管理权限、冻结主体、来源配置/资产市场/日线策略及元数据授权，拒绝未知策略，不将其保存为可执行计划。QTrade独立桥接模块从会话派生scope/actor，明确标的优先否则冻结一个pool快照/摘要；空范围、跨空间、主体注入、非严格确认/整数拒绝。仅DATA_MANAGE+CSRF可变更，read可看；采集内再次查权和CAS。共享CollectionScheduleControl仅携带revision，两端不互相导入运行应用。

工作台独立自动更新panel：折叠创建、日/周/季操作节奏、明确北京时间/回看/补跑/批准、人工ack、保存停用→核对→启用、暂停原因和分页。停用明确不取消已入队工作；冻结范围修改创建新计划。列表保留旧状态并显示读取失败，异步代次和unmount保护防旧响应覆盖新列表；cookie/CSRF由server actions派生，不入浏览器表单。类型化控制schema单独追加，旧schema/产物不变。此阶段日线UI闭环与基础拒绝分组验收，因子/研究策略、撤权/实际重启/修订全矩阵仍未完成，7.x继续不勾选。

真实600036日线原范围首次history为0，后续有界源诊断相同范围5条；日线MINUTES=0未发现一天偏移，不据空响应推导无权限/不支持。原job在部署UI明确重试空分段，既有Worker真实来源恢复5条，原request/part及0行回执保留，不新建/覆盖成功产物。测试等待异步server action接受后才解释终态；首轮提前观察旧no_data时实际动作已接受，最终以显式只读观察模式验证数据库/归档/正确冻结图表及刷新，区分动作与观察。具体供应商变化原因未知；证据COLLECTION-EMPTY-RECOVERY-2026-10-14.md，不代替完整恢复/新鲜度矩阵。该阶段只改诊断/测试/文档，产品和部署算法不改。

### 6. 发布质量

Pipeline 为 raw persisted → normalize → quality checked → published → consumer ready；失败记录在各阶段可查询。阻断格式、身份、摘要、必填、范围和不可能数值；类别规则定义缺口/重复/异常严重性。未复权 OHLC 与供应商前复权负值规则不同；日内逐时段缺口不能仅有日点即完整。未知停牌保持缺失，不制造行情。因子可接受 null 需具体原因，异常元数据/公式风险呈警告，不认证全部准确性。

QualityRun 固定规则版本、输入摘要、结果、原因、统计；阻断原始留存。修复后 reprocess 生成新转换/规则产物版本，不修改旧发布。空响应为无观测，有证据休市可解释但不能计价格覆盖。

### 工作台状态语义与可读密度

提交接口只表示任务接受，因此工作台以信息色显示“已提交，等待 Worker 执行”，只有任务/发布实际完成才使用成功色。状态胶囊同时使用文字与颜色：queued/中性、running/进行中、waiting 与部分完成/警告、failed/危险、no_data 与 cancelled/中性；不能再把正常等待套用错误红色。手工标的与股票池在字段旁持续显示当前生效范围，不能只藏在折叠说明中。旧版日线/分钟入口折叠为明确的兼容入口，逐笔归档保持独立分区。

视觉基线以专业研究终端为目标：正文和业务辅助文字至少 11–12px，表单值 13–14px，关键控件边界满足可辨识对比度并使用实心 2px 键盘焦点；一级数据 surface 统一 10px 圆角并减少卡片嵌套。字体通过打包资源自托管，避免不同操作系统回退造成布局和截图漂移。该设计不改变采集、权限、发布或时间语义；真实数据页仍需在部署 UI/API/Worker/来源链路中验收。

质量规则版本采用共享契约中的封闭集合与核心静态 evaluator 注册表，版本名不作为插件或导入路径。新增版本必须同时提供经审查的 evaluator 与契约成员；未知版本在读取或分派时拒绝，不回退当前规则。现有 `collection-quality.v1` evaluator 保持原摘要和结果；Freshness 按每份历史质量的 `rule_version` 重放，离线 Replay 在预览冻结已注册版本，执行按意图中的版本重建并以同版本门禁，避免当前默认版本演进后改写历史语义。本基础不新增分钟、复权或其他类别规则，4.2/4.3 仍按原任务验收。

### 7. 用量、公平性与新鲜度

统一执行网关每个真实请求前原子保留来源/作用域加权信用、并发槽位和日预算，记录完成/失败、响应字节和耗时；因子历史按已知5调用成本，未知费用展示区间。重试/定时/复核共用账本，预览仅估计。确认阈值与硬预算分离；硬预算不可通过确认绕过。来源级与作用域级轮询公平领取，禁止大池耗尽全部槽位长期阻塞其他运行。

新鲜度分 observed/source available/local collected/published 时间，期望来自交易日历与类别规则；来源未更新、本地未采、发布失败分别归因。HealthPort 对外提供状态，OutboxPort 通过公开桥接进入 QTrade 告警，稳定事件键去重，恢复独立事件可追溯。日志只有安全错误码/关联ID，无供应商完整URL或上游原始错误文本。

### 8. 验收、性能与恢复

### 元数据与行情缓存的并发隔离

### 请求整体截止与连接所有权

MaiRuiCollection生产默认使用独立BoundedHttpClient模块。每个已扣账请求由spawn的短生命周期Linux进程持有HTTP连接，父进程从启动前计总截止时间，超时或异常后kill并join，再返回错误和完成账本；不采用无法终止的后台线程超时。子进程设置PR_SET_PDEATHSIG并回查父PID，使Worker死亡关闭连接；来源凭证经进程IPC传递，不放argv/文件。子进程标准输出/错误重定向，错误跨模块只传固定安全码。

父进程调用前检查当前预留有效期减10秒余量，整体请求配置COLLECTOR_REQUEST_TIMEOUT_SECONDS默认90、上限300秒；当前账本租约3600秒。生产解码响应在流读取时限制64MB，超限关闭，不在完整无限下载后才检查；每次连接不复用，换取连接所有权清晰。响应临时目录私有、body/result为0600，正常/超时返回清除；父进程或宿主机突死可能遗留私有临时响应目录，不把此目录当不可变原始归档。

测试分别使用真实本地TCP滴流/超量/Worker死亡与受控账本过期拒绝；本地故障不计供应商故障证据。主机长时间暂停、任意墙钟跳变、多实例租约竞争及用户取消中的连接语义还需验收，尚不以本模块断言完整并发5.1已完成。每请求进程开销需在固定性能基线记录，不隐式外推全市场吞吐。

### 普通历史v3来源标志修复

真实归档发现普通历史sf数值0.0经Decimal无损编码为文本后，旧v2仅接受词法0，导致正常行情被误标suspect。新增mairui.history-bars.v3，仅用于mairui.history.bars，普通股票按有限Decimal的零值解释；缺失/空值保留未知并标suspect，非零警告，布尔/非法/非有限值阻断。普通指数接口未要求股票sf，标记not_applicable并维持OHLC校验，不套用股票停牌语义。增加来源标志语义及未知数量证据，价量/时区/时间标签规则不改。旧v1/v2及Pro版本继续原分支，避免改写冻结引用；Pro各端点同名字段语义不借用普通历史政策，其完整质量矩阵继续待完成。注册当前新版本，旧输入可通过既有显式离线预览从v2到v3生成新发布，原失败/质量/记录均保留。

### 本机认证部署的可重复恢复

为既有13000 Web及3121/3122/3123原生认证进程提供项目内resume/restart入口，不依赖临时脚本。只处理私有进程台账所拥有的三类进程，PID与启动身份、命令、工作目录和独立进程组均核验；端口被其他进程占用时拒绝，不杀外部程序。通过当前Compose依赖地址刷新连接，保留数据库名、身份/会话密钥、对象桶与业务配置，不调用prepare/cleanup创建或删除身份和数据。

恢复模块封装依赖发现、私有启动快照、状态原子写入、进程停止/启动与有界就绪检查；CLI只暴露resume和显式restart。并发恢复用本机文件锁互斥。快照先于停机以0600原子保存，仅保存项目相关配置及必要启动环境，不记录无关工具凭证；新进程启动使用管道闸门，先保存PID/启动身份再放行执行，避免登记失败后遗留未管理服务。就绪超时保留已登记进程，下一次检查同一身份，不因观察超时重复启动。该机制是本机进程恢复，不替代9.5隔离一致备份恢复或跨物理机器部署验收。
