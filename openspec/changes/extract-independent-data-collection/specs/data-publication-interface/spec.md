# 数据发布接口规约

## Purpose

采集与市场终端通过版本化数据契约协作。采集负责提供带来源与覆盖证据的不可变产物，终端或研究消费者负责显示和导入；双方无需读取对方私有表，跨机器部署仍能定位下载与展示之间的问题。

## ADDED Requirements

### Requirement: 多资产身份和名称快照
契约 MUST 区分股票、指数、ETF、期货和加密产品，明确市场、交易场所、产品身份和计价单位；核心不得将六位代码、人民币或A股交易时间作为普遍规则。采集与图表显示简称加代码，来源名称随产物冻结；未知名称明确未核验。

#### Scenario: 同代码跨市场或资产
- **WHEN** 港股、美股、ETF、期货具体/连续合约或加密现货/永续使用相似交易代码
- **THEN** 身份可区分并保存各自名称，未接入产品在创建任务前明确拒绝，不与A股或其他产品的数据互相覆盖

#### Scenario: 标的后续改名
- **WHEN** 新采集观察到名称变更
- **THEN** 新产物保留新名称，旧产物名称与身份不改写；任务和市场图表都显示简称与代码

### Requirement: 版本化清单和分页记录
发布接口 MUST 提供产物身份、作用域、来源、类别、标的、周期、半开UTC范围、原始归档摘要、标准记录数量与摘要、字段映射版本、质量限制和分页记录。股票与指数身份不冲突，数值使用精确十进制文本并声明单位。

#### Scenario: 市场终端消费分钟行情
- **WHEN** 消费者读取已完成的行情产物
- **THEN** 分页得到契约有效的OHLC、股/元量额与原始标签口径，验证清单与记录摘要，未知字段保持为空，来源和数据版本可追踪

### Requirement: 幂等导入与可见性
QTrade MUST 通过发布接口消费数据，分别显示采集完成、导入等待、导入失败和终端可见。导入按产物身份幂等，失败可重试且不会把半导入数据暴露为完整数据集；旧冻结引用保持不变。

#### Scenario: 下载完成但导入中断
- **WHEN** 采集已有非空归档但市场导入失败
- **THEN** 页面保留采集完成并明确展示未就绪，重试后刷新能在市场终端读取真实行情，不显示虚假成功

### Requirement: 因子独立消费
因子 MUST 使用独立类别和数据浏览入口，保留因子身份、定义、交易日、空值原因、来源计算版本和历史可见限制，不包装为K线或自动充当可用于历史回测的财务PIT。

#### Scenario: 浏览空因子值
- **WHEN** 用户查看来源返回null的历史因子点
- **THEN** 界面明确显示空值和可知限制，不显示为零或遗漏该点，不出现在价格K线中

### Requirement: 接口拒绝与端到端验收
接口 MUST 拒绝未知版本、跨作用域、无权限、摘要不匹配和不支持类别。交付记录须区分真实来源、fixture和阻塞，并验证桌面/手机UI建任务、Worker、归档、导入或因子浏览、刷新及异常路径。

#### Scenario: 实际来源失败
- **WHEN** fixture链路通过但实际来源权限或数据拒绝
- **THEN** 保留fixture证据并标实际来源阻塞，不声称真实可用
