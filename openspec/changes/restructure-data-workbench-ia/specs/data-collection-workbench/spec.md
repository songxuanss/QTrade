# Spec Delta

## Purpose

把数据管理页从七个按实现历史堆叠的平级分区,重组为按用户任务流组织的四个视图(数据目录 → 多维下载 → 任务与结果 → 来源与新鲜度),并保证独立采集的创建与结果两半在分属两个视图时仍是同一实例:草稿不丢、轮询不断、反馈通道不错位;所有既有深链接与锚点继续可达。

## ADDED Requirements

### Requirement: 数据工作台四视图信息架构
数据管理页 MUST 以四个顶层视图组织:数据目录(市场/板块/股票池圈定)、多维下载(采集范围配置与计划预览,含财务、分红送转与逐笔兼容下载入口)、任务与结果(采集任务执行详情与数据资产)、来源与新鲜度(来源能力、用量、数据新鲜度与计划调度)。视图切换 MUST 保持非活动视图挂载,不得丢弃进行中的表单草稿、任务轮询或退避计时。

#### Scenario: 主线任务流按视图推进
- **WHEN** 用户从数据目录圈定范围后进入多维下载、预览并提交任务
- **THEN** 提交成功后工作台切到任务与结果视图并展示该任务详情,期间多维下载的表单输入保持原样

#### Scenario: 切换视图不丢草稿
- **WHEN** 用户在多维下载填写了标的与日期,切到任务与结果查看历史任务,再切回多维下载
- **THEN** 此前填写的草稿值完整保留,预览失效语义(改动后需重新预览)不变

### Requirement: 采集创建与结果跨视图单实例
独立采集面板 MUST 以单一实例同时向多维下载视图提供创建半(表单+计划预览)、向任务与结果视图提供结果半(任务选择器+任务详情+已发布记录)。任务自动刷新、退避重试提示与错误反馈双通道 MUST 在拆分呈现下保持既有语义:创建上下文的失败反馈就近内联于表单页脚,结果上下文的失败反馈呈现于结果区横幅,同一错误 MUST 不重复播报。

#### Scenario: 任务轮询跨视图持续
- **WHEN** 一个排队或运行中的任务在任务与结果视图自动刷新,用户切换到多维下载
- **THEN** 轮询不中断,切回后任务详情反映期间收到的最新快照

#### Scenario: 结果半错误不错位到创建半
- **WHEN** 用户在任务与结果视图触发失败(如取消任务被拒)
- **THEN** 失败原因出现在结果区横幅且滚动进入视口,多维下载的表单页脚不出现该错误

### Requirement: 深链接与锚点向后兼容
既有的 `data_view` 旧值(collect/pools/fundamentals/schedules/assets/monitor/ticks)、`collect_view`、`collector_job`、fragment 锚点与嵌套视图参数(research_view/asset_view/monitor_view)MUST 继续把用户带到重组后的对应视图与嵌套分区;SSO returnTo 白名单 MUST 继续只透传这些既有导航键。新产生的链接与重定向 MUST 使用新视图键(catalog/download/jobs/sources)。

#### Scenario: 旧任务深链接落到任务与结果
- **WHEN** 用户打开 `?data_view=collect&collector_job=<id>` 或 `?data_view=collect&collect_view=results`
- **THEN** 工作台选中任务与结果视图并加载该任务详情

#### Scenario: 旧分区链接映射到新视图
- **WHEN** 用户打开 `?data_view=pools`、`?data_view=assets&asset_view=quality`、`?data_view=schedules` 或 `#legacy-downloads`
- **THEN** 分别选中数据目录、任务与结果(质量问题嵌套分区)、来源与新鲜度(自动更新嵌套分区)、多维下载(逐笔与兼容嵌套分区)

#### Scenario: 操作后回到所属视图
- **WHEN** 用户提交兼容下载任务或关闭质量问题,server action 重定向回数据管理页
- **THEN** 重定向使用新视图键并落在操作所属的视图与嵌套分区,不携带凭据或完整用户输入以外的敏感参数

### Requirement: 全局采集范围条
数据管理页 MUST 在四视图标签上方持续展示当前采集草稿的生效范围(类别、标的、日期、来源),并区分继承自数据目录的冻结股票池与本次手工输入。范围条的任一段 MUST 能切回所属视图并聚焦对应控件;范围条 MUST NOT 替代表单校验、预览冻结或提交语义。

#### Scenario: 范围条反映草稿
- **WHEN** 用户在多维下载填写手工标的与日期并选择股票池
- **THEN** 范围条显示股票池成员数、手工标的数、去重后的标的数、日期区间与来源,切到其他视图后内容不变

#### Scenario: 从范围条回到字段
- **WHEN** 用户在任务与结果视图点击范围条的标的段
- **THEN** 工作台切到多维下载并聚焦标的输入控件

### Requirement: 继承态分组
创建表单 MUST 把继承自数据目录的冻结股票池与本次手工输入分组呈现;股票池分组 MUST 提供一键解除继承,并保留手工标的与日期。分组呈现 MUST NOT 改变提交语义:手工标的与池成员仍合并去重,提交时冻结池成员快照。

#### Scenario: 解除继承只影响池
- **WHEN** 用户已选股票池并填写手工标的,点击解除继承
- **THEN** 股票池选择被清空,手工标的与日期保持不变,预览失效等待重新预览

### Requirement: 标的清单抽屉与移动端已选栏
创建表单 MUST 提供可搜索的标的清单抽屉(来源:已保存股票池成员与手工标的),支持批量加入本次范围或将手工标的移出;抽屉 MUST 具备 dialog 语义、焦点循环、Escape 关闭并归还焦点。窄屏(移动)MUST 在视口底部显示已选栏(标的/因子数量与清单入口),且 MUST NOT 造成横向溢出或遮挡提交操作。

#### Scenario: 清单加入本次范围
- **WHEN** 用户在抽屉中搜索并勾选股票池成员后确认
- **THEN** 手工标的输入追加去重后的代码,抽屉关闭并把焦点归还给触发按钮

#### Scenario: 移动端已选栏
- **WHEN** 390px 视口下已有标的或因子草稿
- **THEN** 底部已选栏显示数量与清单入口,打开抽屉可继续编辑,页面无横向溢出且 axe 无违规
