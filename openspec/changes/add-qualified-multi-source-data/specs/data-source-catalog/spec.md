# Spec Delta

## Purpose

按类目、权限、历史覆盖与实际运行证据选择数据供应商，使用户能明确下载来自哪一来源及其能力限制；来源不可用或替换时仍保持计划、原始产物和研究引用可核对。

## ADDED Requirements

### Requirement: 来源能力证据分级
来源目录 MUST 区分文档描述、已配置、样本验证、端到端验证和阻塞状态，公开适用类目/字段/周期/市场、历史范围证据、更新与限额限制；套餐名称不等于实际权限。

#### Scenario: 正式版不含扩展权限
- **WHEN** 已配置正式版证书但扩展分钟接口实际拒绝
- **THEN** 系统保留基础能力的独立状态，不显示扩展已接通，不以本地开关声称获得订阅

### Requirement: 按类目选择可用来源
单标的及整池下载 MUST 只允许选择当前已配置且支持请求类目/周期的来源，预检校验作用域、字段、范围和授权，提交冻结来源、授权非秘密身份与转换版本。

#### Scenario: 请求另一来源不支持的类别
- **WHEN** 用户选择日线来源下载成交逐笔或尚未配置账号的来源
- **THEN** 页面明确禁用原因，直接请求也在创建任务前拒绝，不伪造可用任务

### Requirement: 多源产物与覆盖分离
系统 MUST 按来源、类目、标的、时间、调整与转换口径核算已有/缺失覆盖。不同来源结果并存，对账保留差异及依据；不会自动拼接进入同一冻结产物。

#### Scenario: 主源限流时已有另一来源数据
- **WHEN** 冻结主源下载遇到429且另一源有同范围记录
- **THEN** 保留主源等待/失败，另一源数据可独立展示或显式新建计划，不冒充主源完成，不改写旧研究引用

### Requirement: 接入必须完成真实链路验收
来源 MUST 完成真实UI建任务、Worker消费、提供方返回、非空归档、适当标准结果及刷新可见后，才能将对应范围/类目标为已接通；fixtures与其他账号/套餐的结果分别记录。

#### Scenario: SDK样例成功但Worker未完成
- **WHEN** 来源样例返回数据，而项目实际后台或持久化未完成
- **THEN** 目录最多显示样本验证，不显示端到端可用或下载成功

### Requirement: 凭证保持私有
供应商凭证 MUST 只存在授权的私有配置或秘密存储，API、DTO、日志、报告、截图及版本库不得包含秘密；轮换后执行进程确认新配置，既有产物保持身份与版本。

#### Scenario: 更新供应商证书
- **WHEN** 用户授权替换并持久保存证书
- **THEN** 私有配置被更新且执行进程加载新值，公开验证只记录是否匹配与能力结果，不返回凭证内容
