# Spec Delta

## Purpose

提供可信、可追溯、可回放的市场与资产主数据能力，为分析、告警、回测和交易提供统一输入。

## ADDED Requirements

### Requirement: Instrument Master
系统 MUST 维护目标市场 Instrument 的唯一标识、交易所、货币、精度、最小价格变动、最小交易数量、合约乘数、交易时段与状态；用户 MUST 能按标识、名称、交易所和市场筛选。

#### Scenario: 查询标的规格
- **WHEN** 用户打开某个 Instrument 详情
- **THEN** 系统展示其交易所、精度、最小变动、交易时段、合约规格与当前启用状态

#### Scenario: 标识冲突
- **WHEN** 数据源返回与既有 Instrument 关键规格冲突的更新
- **THEN** 系统生成待处理数据质量问题，不静默覆盖已用于历史回测的规格

### Requirement: 交易日历约束
系统 MUST 维护目标市场交易日历、时区和交易时段，并用于数据补采、回测时间边界和实盘市场状态判断。

#### Scenario: 非交易时段下单
- **WHEN** Live Runtime 在市场关闭时段产生 Order Intent
- **THEN** 系统按配置拒绝、排队或要求审批，并说明市场状态原因

### Requirement: 历史数据幂等采集
历史行情采集 MUST 支持分批、重试、限流与断点续采；同一数据源、标的、时间与粒度的重复导入 MUST NOT 产生重复标准化记录。

#### Scenario: 采集任务重跑
- **WHEN** 管理员重跑一个已部分成功的历史采集任务
- **THEN** 系统只补采缺失部分，已有正确数据不被重复写入

#### Scenario: 供应商限流
- **WHEN** 数据源返回限流或临时错误
- **THEN** 任务按退避策略重试，记录错误与下次尝试时间，不标记为成功

### Requirement: 标准化行情查询
系统 MUST 通过统一契约提供 Instrument、时间范围、粒度的 OHLCV 查询，并返回时间戳、时区、数据完整性与来源批次信息。

#### Scenario: 查询 K 线
- **WHEN** 授权用户请求某标的指定时间范围和周期的 OHLCV
- **THEN** API 返回按时间升序排列的标准 K 线，并包含数据质量状态

#### Scenario: 超出可用范围
- **WHEN** 用户请求的时间范围没有已采集数据
- **THEN** API 返回空结果与明确边界信息，不伪造数据

### Requirement: 实时行情健康
实时行情连接 MUST 检测心跳、延迟、断线与乱序，并在恢复后补齐可补数据；连接状态和数据延迟 MUST 对授权用户可见。

#### Scenario: 行情断线
- **WHEN** 实时供应商连接断开
- **THEN** 相关页面显示降级状态，系统记录事件并尝试重连

#### Scenario: 延迟超过阈值
- **WHEN** 某市场实时行情延迟超过配置阈值
- **THEN** 系统产生数据告警，并按配置暂停依赖该数据的新实盘订单

### Requirement: 数据质量检测
系统 MUST 对缺失、重复、乱序、异常跳价、成交量异常和交易日历偏差执行质量检查，并生成可查询、可认领、可关闭的 Data Quality Issue。

#### Scenario: 发现缺口
- **WHEN** 某标的分钟 K 线在交易时段内缺失
- **THEN** 系统生成 Data Quality Issue，标明缺口范围、影响数据集和检测结果

#### Scenario: 异常跳价
- **WHEN** 输入价格超过配置的跳变阈值
- **THEN** 系统隔离该记录或标记异常，不静默作为正常数据参与回测

### Requirement: 数据血缘与不可变批次
每条标准化数据 MUST 能追溯到来源、授权、采集任务、Data Batch、转换规则与质量检查结果；原始 Data Batch MUST 不可变并可重放生成新的数据集版本。

#### Scenario: 追溯异常数据
- **WHEN** 用户从 Data Quality Issue 打开影响记录
- **THEN** 系统展示原始批次、来源响应摘要、转换版本与入库时间

#### Scenario: 重放原始批次
- **WHEN** 管理员用新版转换规则重放既有 Data Batch
- **THEN** 系统创建新的 Market Dataset 版本，不修改旧版本及其历史回测引用


### Requirement: 用户指定历史范围与配置上限
系统 MUST 允许用户指定 A 股逐笔、未复权日线及已配置历史分钟周期的范围；逐笔单次时长上限 MUST 可配置，默认不限。来源归档边界与授权仍 MUST 生效，不得把无本地上限解释为来源有无限历史。

#### Scenario: 修改逐笔时长配置
- **WHEN** 管理员配置正整数天数上限或不限
- **THEN** API 与页面使用相同策略，超限拒绝建任务，不限时允许超过七天的请求

#### Scenario: 未配置分钟授权
- **WHEN** 用户选择需要额外授权且当前未配置的分钟周期
- **THEN** 页面禁用该周期，直接 API 请求也在创建任务前拒绝

### Requirement: 长范围下载自动拆分
系统 MUST 将超过七个自然日的下载范围拆成连续且互不重叠的半开区间子任务，每个子任务 MUST 不超过七日，最后一段保留原结束时间。整体范围上限仍使用既有可配置策略，默认不限。来源授权与历史边界 MUST 在创建所有子任务前验证。子任务 MUST 独立持久化、消费、重试和审计，界面 MUST 展示分段编号和范围；不得以单个子任务成功代表整个范围完成。

#### Scenario: 九天请求
- **WHEN** 管理员提交九天的合法下载范围
- **THEN** 系统原子创建七天和两天两个子任务，返回全部任务标识，二者并集恰好等于请求范围

#### Scenario: 部分已有数据
- **WHEN** 用户选择仅下载缺失数据且一个缺失区间超过七天
- **THEN** 仅对缺失区间再次按七天拆分，保留已完成批次，失败子任务单独重试

#### Scenario: 已下载日线在市场终端查看
- **WHEN** 下载的 601288.SH 日线已转换入库且用户直接打开该标的图表
- **THEN** 市场终端根据该标的已发布数据自动选择可用周期，仅有日线时默认 1d 和一个月范围，显示实际日线数据，刷新保留；未下载的分钟周期明确提示周期不匹配，不将下载时长解释为失败

### Requirement: 完整性与研究前提可见
系统 MUST 保存已下载历史行情的来源交易日历证据，并通过不可变报告展示预期交易日、观察到的交易日和缺失日期。采集完成 MUST NOT 表示盘中数据完整、复权验证通过、历史证券池完整、财务 PIT 或真实交易就绪。

#### Scenario: 查看历史行情覆盖
- **WHEN** 用户打开已完成历史行情数据集的质量报告
- **THEN** 展示已保存记录数、交易日覆盖、缺失日期及尚未核验的研究前提；刷新后内容保持一致

#### Scenario: 缺少某个交易日
- **WHEN** 来源日历预期交易日没有观察到该标的行情
- **THEN** 报告明确标记缺口，不无证据解释为停牌，也不生成补齐行情
