# Spec Delta

## Purpose

定义 QTrade 作为低耦合专业交易平台的基础架构行为，确保引擎、数据源、券商、研究框架与存储可以独立替换且不破坏用户可见能力。

## ADDED Requirements

### Requirement: 外部系统通过稳定契约接入
QTrade 的核心业务行为 MUST 通过稳定契约访问交易引擎、市场数据、券商、研究框架、对象存储与通知系统；替换适配器 MUST NOT 要求重写用户认证、策略生命周期、风控、审计或主 UI 工作流。

#### Scenario: 替换交易引擎适配器
- **WHEN** 管理员将某个 Workspace 的回测引擎从 LEAN 适配器切换为兼容的备用适配器
- **THEN** 用户仍使用同一回测创建、任务查询、报告与对比界面，仅结果中记录的引擎标识和版本发生变化

#### Scenario: 外部 SDK 不可用
- **WHEN** 某个行情供应商或券商适配器不可用
- **THEN** QTrade 核心服务仍能处理登录、查看已有数据、管理策略和查询历史任务，并将该适配器能力显示为降级

### Requirement: 计算任务隔离运行
回测、研究计算和实盘运行时 MUST 在独立 worker 或容器中执行，并受 CPU、内存、执行时长、网络与文件系统访问限制；任务失败 MUST NOT 导致 API 服务崩溃。

#### Scenario: 策略任务超时
- **WHEN** 一个回测任务超过配置的最大执行时间
- **THEN** QTrade 终止该任务、释放隔离资源，并将任务标记为失败且保留失败原因

#### Scenario: 恶意策略尝试访问网络
- **WHEN** 未获得授权的策略代码在沙箱中尝试访问外部网络
- **THEN** QTrade 阻止该访问、记录安全事件，并使校验或运行失败

### Requirement: 产物不可变且可追溯
每个回测、研究与执行产物 MUST 关联不可变 Artifact Manifest，至少包含创建者、时间、代码版本、数据集版本、参数版本、引擎/适配器版本和环境镜像摘要。

#### Scenario: 查看回测输入
- **WHEN** 用户打开一个历史回测报告
- **THEN** 系统展示该回测使用的代码、数据集、参数、引擎和环境版本，且这些输入不能被后续编辑覆盖

#### Scenario: 数据集被修正
- **WHEN** 某个市场数据集在新版本中被修正
- **THEN** 已完成的历史回测继续引用旧版本 manifest，不自动改变结果

### Requirement: 标准结果模型
不同引擎、数据源和券商适配器返回的私有格式 MUST 转换为 QTrade 标准结果模型；UI 与核心 API MUST NOT 依赖某个外部项目的私有结果结构。

#### Scenario: 两个引擎输出同一结果类型
- **WHEN** 两个兼容引擎分别完成相同类型的事件驱动回测
- **THEN** 两者的权益曲线、订单、成交和指标都进入同一标准结果结构，并可在同一页面比较

### Requirement: 能力声明
系统 MUST 为每个引擎、数据源和 Broker Adapter 暴露能力声明，包括支持的市场、数据粒度、订单类型、交易时段、实盘能力与当前健康状态；不支持的能力 MUST 在 UI 与 API 中不可用或明确标记不可用。

#### Scenario: 适配器不支持某订单类型
- **WHEN** 用户选择的 Broker Adapter 不支持止损止盈组合单
- **THEN** 下单界面禁用或拒绝该订单类型，并说明不支持的原因
